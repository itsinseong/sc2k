## 1. 한 줄 콘셉트

> 전세대출 신청 여정 안에서, 지금까지 세입자가 혼자 판단해야 했던 위험(깡통전세·보증취소·잔금일)을 인터페이스가 근거와 함께 눈으로 보여주는 인터랙티브 웹 서비스.

탐지 모델을 만드는 프로젝트가 아니라, **탐지 결과를 사람이 이해하고 행동하게 만드는 경험 설계** 프로젝트다.

---

## 2. 배경 — 왜 이 문제인가

1. **위험 판단이 전부 세입자 몫이다.** 깡통전세·이중계약·무자본 갭투자 위험을 은행 신청 단계에서 걸러주지 않는다. (로지움허브 2026 체크리스트)
2. **잔금일 리스크가 구조적으로 존재한다.** 보증기관(HUG·HF·SGI) 심사는 5~10영업일, 복잡한 건은 2주 이상 걸리는데 그 시간 리스크를 세입자가 떠안는다. (내집스캔 블로그)
3. **아는 사람이 드문 함정이 있다.** 보증보험에 가입해도 전입을 빼는 순간 대항력이 상실되어 보증이 취소될 수 있다. (HUG 보증 약관)
4. **정보 공개는 늘어나는데, 이해로 이어지는 설계는 없다.** 정부 전세사기 방지대책(2026.3)으로 안심전세앱이 9월 대개편된다 — 정보 57종 통합, 선순위 보증금·임대인 체납 등급 공개, 직방·네이버부동산 등 민간 연계 추진. 그러나 공개 형태는 등급·점수형이고, 은행권 대응도 심사 자동화(신한, 2026.4)와 보험(하나 '청년지킴이')에 머문다. (2026-07-17 현업 리서치 — `현업비교_리서치_2026-07-17.md`)

**결론: 문제는 "정보가 없다"가 아니라 "늘어나는 정보가 세입자의 이해와 행동으로 이어지지 않는다"이다. 이 프로젝트는 그 마지막 구간을 설계한다.**

## 3. 주제 근거 — KB AI Challenge 수상작 필터 분석

1~7회 입상·특별상 38건 + 8회 현직자 Pick 6건 분석(본선진출-탈락작 제외). 반복 수상 4축:

| 축 | 대표 사례 |
|---|---|
| 고객 보호·사기 방지 (최다) | 전세사기 예방 블록체인 OCR(4회), 피싱 탐지(3·5·6회), 독소조항 검토(4회) |
| 금융 포용·접근성 | 음성인증(5회), 깨비 할머니 통장(7회) |
| 어려운 금융을 이해시키기 | KB:OT(6회), Kard-Toon(6회 최우수), 설명가능 신용위험(7회) |
| 행원 업무 그라운딩 | DocSearch(5회), 컴플라이언스 LiivAssist(4회) |

탈락작 공통점: 은행의 실제 프로세스·데이터에 접지되지 않은 범용 아이디어(투자보조·메타버스·GAN 굿즈).

### 차용 매핑

| 차용 원천 | 성적 | 가져온 것 → 바꾼 것 |
|---|---|---|
| 전세사기 예방 블록체인 OCR | 4회 입상 | 문제의식 → 계약 시스템에서 **대출 신청 플로우 내장 UX**로 |
| 설명 가능한 신용 위험 모니터링 | 7회 입상 | 투명 공개 원칙 → 투자자 리포트에서 **세입자용 근거 카드**로 |
| KB:OT | 6회 입상 | 금융 번역 → 텍스트에서 **시각·조작형 번역**으로 |
| Kard-Toon / KB Athena | 6회 최우수 / 5회 입상 | 데이터→생성형 콘텐츠 구조 → **맞춤 확인 목록 생성**으로 |

## 4. 타겟과 사용자 시나리오 — 3막 구조

**타겟: 첫 전세 계약을 앞둔 20대 사회초년생·대학생** (사용자 테스트 리크루팅이 주변에서 가능한 집단)

- **1막 · 매물 입력** — 시군구·단지·전용면적을 고르면 실거래가 기반 시세가 로드된다. 보증금·계약일·잔금일을 넣고, 등기부에서 확인한 선순위 채권·신탁 여부를 입력한다.
- **2막 · 위험 시각화** — 실질 전세가율·선순위 채권·신탁·체납 확인 여부가 근거 카드로 펼쳐진다.
- **3막 · 조건 이해와 의사결정** — 보증취소 조건과 심사 타임라인을 직접 조작해보고, 내 매물 조건에 맞는 "계약 전 확인 목록"을 들고 나간다.

## 5. 핵심 인터랙션 3종 (이것이 미디어 산출물)

### ① 위험 근거 카드
위험도를 점수 하나로 뭉개지 않는다. 신호마다 카드 한 장 — 앞면은 신호 한 줄, 펼치면 **계산식·근거 실거래·설명문**이 드러난다. (7회 수상작의 설명가능성 원칙을 UI로)

### ② 잔금일 타임라인 시뮬레이터
계약일~잔금일 타임라인 위에 보증기관 심사 소요(5~10영업일) 밴드를 겹쳐 그린다. **잔금일을 드래그하면 리스크 구간이 실시간으로 변한다.** 여유 영업일 <10 주의, <5 위험.

### ③ 보증취소 what-if 워크스루
전입신고·확정일자·전입유지 토글 3개. **"전입을 뺀다"를 직접 조작하면 대항력 상실 → 우선변제권 상실 → 보증 취소가 연쇄로 시각화**된다. 가장 알려지지 않은 함정을 체험으로 학습시킨다.

## 6. 생성형 AI 레이어 — 판정과 설명의 분리

**원칙: 판정·수치는 룰과 데이터가 결정한다. LLM은 "세입자 언어로의 번역"만 담당한다.**

- 근거 카드 설명문: 구조화 신호("선순위 채권 1.2억")를 내 상황 문장("경매 시 은행이 먼저 1.2억을 가져가고, 내 보증금은 그 다음 순위")으로
- what-if 내레이션: 조작 결과를 상황 설명으로
- 계약 전 확인 목록: 매물 조건 맞춤 생성

LLM 입력은 구조화된 판정 결과만 받는다(자유 텍스트 금지). **판정 로직에 LLM이 개입하는 순간 환각 방어가 무너지므로 범위 확장을 금지한다.** 화면에 "참고용 설명" 고지. API 실패 시 룰 기반 고정 설명문으로 폴백.

## 7. 실데이터 경계 — 무엇이 진짜이고 무엇이 입력인가

프로토타입이 아닌 실제 동작 서비스로 만든다. 단, 데이터별 경계를 정직하게 긋는다:

| 데이터 | 연동 | 방법 |
|---|---|---|
| 시세 (전세가율 분모) | **실데이터** | 국토부 실거래가 공공 API — 최근 6개월 전세 실거래 중앙값으로 추정, 근거 거래를 화면에 노출 |
| 보증 기준 룰 | **실제 규정** | HUG 담보인정비율 90%(2023.5~) 등 공개 규정을 룰 엔진으로 |
| 위험 설명문 | **실제 LLM** | Claude API 호출 (번역만) |
| 등기부 (선순위·신탁) | 사용자 입력 | 상용은 유료 B2B 대행 API(CODEF — 존재 확인, 구독형·협의 필요)로 자동화하는 영역. v1은 "직접 열람 후 입력" + 사유 화면 명시, 확장 시 CODEF 연동 가능한 구조로 설계 |
| 임대인 체납 | 사용자 확인 | 임대인 동의 필요 영역 — 납세증명서 요구 안내로 대체 (2023.4부터 임차인 열람권 보장) |

이 경계를 숨기지 않고 화면에 명시하는 것 자체가 서비스의 신뢰 설계이자 발표 방어 포인트다.

## 8. 기술 구현

- **스택**: Next.js 15 + React 19 + TypeScript + Vitest (`kb-youth-housing` 검증된 패턴 재활용)
- **룰 엔진**: 순수함수 판정 모듈 3종 — risk(전세가율·플래그), timeline(영업일 계산), whatif(상태기계) + 단위 테스트
- **시세 API**: 서버사이드 라우트에서 국토부 API 호출, 키 없으면 수동 입력 폴백 (키 없이도 전체 플로우 동작)
- **디자인**: 에디토리얼 톤(화이트 캔버스·차콜·헤어라인·필 라벨) — 발표덱과 통일
- **배포**: Vercel
- **표기 원칙**: 기획·설계·리서치·검증 = 본인, 구현 = "AI를 활용해 구현"
