## ⚠️ 최우선 — 코드 로직에 반영해야 할 2026년 법리 변경 3건

기존 `src/lib/whatif.ts`, `src/lib/risk.ts`가 구법 기준으로 작성돼 있어 **로직 수정이 필요**하다.

### 1. 대항력 효력 "즉시 발생" (whatif.ts 영향)
- **구법**: 전입신고해도 대항력은 "다음날 0시"부터 발생 — 그 사이 집주인 근저당은 접수 즉시 효력 → 잔금일 당일 대출 사기의 원인이었음
- **신법**: 전입신고 처리 "즉시" 대항력 발생
- 시행 근거: 2026-03-10 관계부처 합동 「전세사기 방지 대책」
- **코드 영향**: `whatif.ts`의 대항력 판정이 "다음날부터"라는 구법 전제로 짜여 있다면 즉시발생으로 갱신 필요. 이게 what-if 시뮬레이터의 핵심 서사("잔금일 당일 대출 사기")를 반으로 줄이는 변화라, 화면 문구도 "이제는 즉시 보호받는다"는 안전 서사로 톤 조정이 필요할 수 있음

### 2. 보증금 "1/3 국가 선지급" 제도 (risk.ts에 새 필드 필요)
- 근거: 2026-04-23 국회 통과 전세사기 특별법 개정안
- 피해 인정 한도: 보증금 5억 → **7억으로 상향**
- 지급: 경매 결과와 무관하게 **국가가 보증금의 최소 1/3(33.3%)을 책임** — 예: 3억 중 한 푼도 못 건지면 국가가 1억 지급, 5천만원만 건지면 부족분 5천만원 추가 지급
- 절차: "선지급 후정산" — 국가가 먼저 주고, 경매/공매 완료 후 회수·정산. **2026년 하반기부터 본격 시행**
- **코드 영향**: 현재 `risk.ts`는 danger 판정만 하고 "그 다음 안전망"이 없다. 3막 체크리스트나 2막 결과 화면에 "최악의 경우에도 최소 33%는 국가가 보장한다"는 안내를 추가하면 공포 조성형 UX에서 "위험을 알려주되 절망시키지 않는" 균형이 생김

### 3. 은행 실시간 금융 연계 시스템 (risk.ts 판정 근거 강화)
- 은행이 대출 실행 시 **확정일자 정보+선순위 보증금 현황을 실시간 조회** 가능 (기존 일부 시범 → 1·2금융권 전체로 확대)
- 임대인의 "임차인 몰래 중복대출" 원천 차단 목적
- **코드 영향**: 지금 앱은 "은행이 조회 불가하니 세입자가 스스로 확인"이 전제인데, 이 변화로 "은행도 이제 실시간으로 보고 있다"는 맥락이 생김 → 리스크 서사를 "너 혼자 확인해야 한다"에서 "은행도 보지만, 너도 알아야 한다(신청 전 협상력)"로 조정 가능

## 콘텐츠 보강 — 지금 3개 화면에 없는 시나리오

1. **다가구주택 선순위 보증금 추정** — 개별 등기 불가라 파악이 원래 어려움. 서울시 「전세사기 위험분석 보고서」(AI, 빅데이터 기반 24종 항목, 무료)가 실무 사례. 공인중개사가 통합정보시스템으로 선순위 보증금을 임차인에게 설명할 **법적 의무**가 있음(계약 전 브리핑 요구 가능)
2. **신탁 사기 시나리오** — 소유권이 신탁회사에 있는데 수탁자(신탁사) 동의 없이 계약 시 대항력 자체가 없음. 확인법: 등기부에서 신탁 여부 우선 확인 → 신탁이면 "임대차 계약 승낙서" 실물 대조 필수. `risk.ts`의 `trustRegistered` 플래그는 이미 있으나, "승낙서 확인 여부"까지는 없음 — 필드 추가 여지
3. **임대인 변경 시 통보 의무** — 세부는 노트북에 짧게만 언급, 추가 확인 필요
4. **안심전세앱 2026-09 개편** — 이전 리서치(2026-07-17)에서 확인한 내용과 일치 + 상세: 임대인 동의 하에 등기·체납·대출연체 정보까지 통합 조회 가능해짐

## UI/UX 레퍼런스

| 사례 | 패턴 | 우리 앱 적용 지점 |
|---|---|---|
| Credit Karma | 점수 변화 원인을 구체적 행동(한도소진율 등)에 매핑해 시각화 | 위험 근거 카드의 "계산식 펼치기" 이미 유사 — 근거를 더 행동 지향적 문장으로 |
| Wealthfront | 리스크 설문 답변→자산배분 인과관계를 그래프로 연결 | what-if 3노드 체인이 이미 이 패턴 |
| **안심전세앱 3.0** | 난해한 권리관계를 안심/주의/위험 "신호등"으로 번역 | 우리 grade(safe/caution/danger) 배지와 정확히 같은 구조 — 이름 대신 신호등 색 강조 검토 |
| Nicky Case | 사소한 규칙이 거대한 패턴을 만드는 과정을 인터랙티브로 학습 | what-if의 "전입을 뺀다" 프리셋과 같은 철학 |
| NYT "Rent vs Buy" | 슬라이더로 변수 조정 → 실시간 비용 역전 지점 확인 | 잔금일 타임라인 시뮬레이터와 직접 대응하는 레퍼런스 |
| Stripe | 박스 없는 얇은 구분선+타이포 계층만으로 정보 구획 | 지난 세션에 이미 이 방향으로 리디자인 완료 — 방향 확인됨 |

## 캐릭터 — 결론: 넣지 않는다

- 성공 사례: 듀오링고(강한 페르소나) vs 토스(축하·빈 화면 등 특정 상황에만 감정 개입)
- **전세사기 같은 심각한 주제엔 "공감형 가이드"나 "전문가 페르소나"가 적합**, 과하게 귀여운 캐릭터는 긴박함을 해침
- **보고서 최종 추천: 캐릭터 없이 "인터페이스 자체가 반응하는 방식"**
  - Expandable line items (Stripe식 클릭 시 펼침) — 이미 구현됨
  - 전입신고 토글 끌 때 "대항력 보호막이 부서지는" 시각 효과 (Wow Point)
  - 타이포그래픽 반응성: 안전(부드러운 차콜)→위험(날카로운 레드)으로 텍스트 톤 자체가 즉시 변하는 모션

→ 캐릭터 제작에 시간 쓰지 않고, what-if 화면의 "붕괴 모션"과 위험도별 타이포 컬러 반응에 투자하는 게 근거 있는 선택.
