### 세부 근거

> (e) Composition report. By noon on the last day of each month, a permitted payment stablecoin issuer must publish the monthly composition of the issuer's reserves held pursuant to the GENIUS Act as of noon on the last day of the previous month on the website of the issuer, using a format substantially similar to the template provided in table 1 to this paragraph (e)

## 2. 재정리본

### 2.1 무엇인가

- 한 줄. 해외 준비금 공시 요건과 양식을 비교해 한국 적용 공시안을 설계하고, 실제 발행사 자료로 수치, 기준일, 누락을 확인하는 웹 프로젝트. 담당자의 근거 확인과 고객의 정보 이해가 개선되는지 평가한다.
- 이름은 StableWatch 유지. 부제 "원화 스테이블코인 준비금 공시 판정기"를 쓰면 판정 대상을 명시한다. 공개 정보의 일치 여부와 제안 공시안의 항목 충족 여부이지, 법규 준수 인증이나 현재 환매 가능성 인증이 아니다.
- 은행 디지털 기획 연결 근거는 IBK 2026 채용 안내의 디지털 역량(신기술 이해, 서비스 기획 경험, 데이터 분석과 활용). 합격을 보장하는 근거는 아니다.
- 현 상태. 조사와 PRD 초안만 있고 파서, 규칙 엔진, 웹은 레포에 없다. 부족한 것은 아이디어가 아니라 설계 선택을 보여줄 실행물과 검증 기록이다.

### 2.2 사용자

- 1차. 월간 준비금 공시에서 수치, 기준일, 누락 항목, 원문을 확인하는 담당자. 은행 내부 업무 흐름 조사가 없으므로 가설. 화면 A.
- 2차. 공시 수치와 정보의 한계를 이해해야 하는 고객. 화면 B는 안내 화면.

### 2.3 구조와 설계 선택 기록

해외 원문 → 한국 적용 고려사항 → 설계 선택 → 데이터와 계산 → 화면 안내 → 검증과 수정.

- 해외 규정마다 적용 대상, 법적 상태, 확인 날짜를 기록한다. 한국은 확정 규정, 공식 검토 방향, 보도, 본인 제안 4층으로 구분한다. OCC 템플릿은 "제안 규정문에 있음, 최종 미확정"으로 적는다.
- "한국 공시안 v1"은 본인이 정하는 설계 기준이다. 해외 값을 가져올 때 한국에서 필요한 이유, 자료 확보 가능성, 정보 시차, 검토 부담, 대안을 적는다. 가장 엄격한 해외 값을 자동 채택했다고 가장 타당한 한국 기준이 되지는 않는다. 이 원칙은 매니페스트_v2 F14의 "값이 좁은 쪽을 기본 채택"과 충돌한다(§3-6).
- 설계 선택 하나마다 기록 형식: 문제 / 해외 근거 / 한국 적용 가정 / 선택한 기준과 표현 / 대안과 선택 이유 / 예외 처리 / 검증 방법. 예: 공시 기준일을 상세 화면에만 둘지 준비금 비율 옆에 둘지는 설계 선택이고, 사용자가 기준시점을 이해하는지로 검증한다.
- 해외 실데이터는 한국 공시안 항목을 채울 수 있는지와 산식과 표시가 작동하는지 시험하는 용도다. USDC 달러 데이터를 한국 발행사의 원화 데이터처럼 표시하지 않는다.

- 기여는 해외 사례 이해, 한국 적용안 선택, 실데이터와 화면 구현, 결과 평가 과정에 있다. 국가 수와 규칙 수는 수준 증명이 아니다. "Tessera 대비 3 대 10"은 측정 근거가 없으므로 삭제한다.

### 2.5 GPT 비교 입장

- "GPT는 못 한다"를 차별점으로 삼지 않는다. 기여는 항목, 범위, 산식, 예외, 고객 문구를 결정하고 반복 작동하게 만들고 검증한 데 있다.
- 주장 가능한 효과 후보: 반복 검토 일관성, 원문 확인 편의, 자료 누락 식별, 고객 오해 감소. 측정된 것만 주장한다.
- GPT와 비교한다면 같은 원문, 공시안, 규칙, 질문과 충분한 프롬프트를 주고 계산 도구도 허용한다. 모델, 날짜, 프롬프트를 기록한다. 정확도가 같아도 근거 확인 시간이 줄면 그 효과를 보고한다. 개선이 없으면 그대로 기록한다.

### 2.6 데이터 접근 범위

| 데이터 또는 판단 | 접근 가능 범위 |
|---|---|
| 공개된 준비금, 유통량, 기준일, 자산 구성 | 공개 보고서로 가능 |
| 계산, 대사, 월별 비교 | 정의, 시점, 통화를 맞추면 가능 |
| Circle Reserve Fund 내부 보유자산 | SEC N-MFP3로 가능, 추가 구현 필요 |
| 개별 은행계좌 잔액, 은행별 현금 배분 | 공개 자료로 불가 |
| 지금 인출 가능한 현금, 고객별 환매 처리 상태 | 운영기관 데이터와 권한 필요 |
| 실제 은행 업무의 처리시간, 비용, 고객 행동 | 현업 협조 필요 |
| 한국 발행사의 실제 준비금과 환매 데이터 | 없음. 시나리오와 구분 |

- N-MFP 중복 계산 주의. Circle Reserve Fund 60,717,246,965달러는 이미 준비자산 71,904,101,332달러 안에 들어 있다. N-MFP는 그 펀드의 내부 구성이므로 준비금에 다시 더하면 안 된다. OCC 템플릿 주석 3도 같은 취지다.
- 추출 주의점. 한 PDF에 기준일이 두 개라 열을 구분해야 한다. 괄호 음수 정산조정액을 포함해야 한다. 1페이지 일부 문자는 글꼴 매핑 문제로 깨져 원문 화면 확인이 필요하다. 회계사 서명일(2026-08-27)과 웹 공개일을 같은 날짜로 취급하지 않는다.
- BlackRock CSV는 약관이 자동 수집과 재배포를 금지한다(2026-09-05 원문 확인). 핵심 데이터원으로 삼지 않는다. 허가 요청 메일은 2026-09-06 발송, 답장 없음.
- 핵심 구현은 Circle PDF만으로 시작할 수 있다.

### 2.7 이번 학기 범위

핵심으로 고정:
- 해외 제도 비교와 한국 공시안.
- 실데이터는 발행사 한 곳, 최종 3~4개월 자료.
- 핵심 항목 5묶음: 준비금과 유통량, 기준시점, 자산 구성과 합계, 외부 검증 정보, 누락과 근거 표시. 세부 체크는 실제 자료에 맞춰 확정.
- 화면 두 개: 담당자 확인 화면, 고객 공시 안내 화면.
- Python으로 미리 처리한 JSON을 정적 웹이 읽고, 사용자는 준비된 보고서를 선택한다. 업로드 흐름 없음.
- 원문 확인, 누락과 불일치 처리, 작은 검증과 수정.

후순위: SEC 세부 파서, 다수 발행사, 해외 모든 규정의 실행 설정, 실시간 수집, 한국 규정값 자동 추천, 온체인 재구성. 실제 환매 처리와 현재 환매 가능 여부 판정은 이번 범위에서 다루지 않는다. 자동 파싱이 막히면 수작업 검증 JSON으로 프로토타입을 완성하되 수동과 자동 범위를 표시한다.

### 2.8 검증 설계

- 정확성. 원문 위치, 기준값, 산식, 예상 상태를 담은 기준표로 확인한다. 가능하면 별도 검토자가 수치와 근거를 본다. 합의되지 않은 법률 해석은 정답으로 고정하지 않고 쟁점으로 분리한다. Tessera 팩은 외부 비교 자료이지 독립 정답표가 아니다.
- 자료 분리. 개발용과 평가용을 나눈다(예: 4개월 중 3개월 개발, 1개월 평가). 평가 사례는 정상, 누락, 시점 불일치, 합계 오류 등 약 12개로 시작하고 실제 자료와 변형 사례를 구분한다. 수정 후에는 수정 전후 평가를 따로 기록한다. 12라는 수는 추정이다.
- 사용자. 4~6명에게 근거 찾기, 기준일 이해, 확인 불가 정보 식별 과제를 준다. 비슷한 난도의 다른 자료를 쓰고 순서를 교차해 학습 효과를 줄인다. 소수 비전문가 실험은 탐색적 평가이고 은행 실무 효율이나 법적 정확성을 입증하지 못한다.
- 측정 항목. 수치와 근거 정확성, 잘못된 통과 판정 건수, 올바른 근거를 찾는 시간, 내용 이해 여부. 최초 구축과 정답표 작성 시간과 반복 검토 시간을 따로 기록한다. 작은 평가의 성적과 일반 성능을 구분한다(NIST 2026-02-17).

### 2.9 자문과 일정

| 대상 | 요청할 조언 | 준비물 |
|---|---|---|
| 경제학과 교수(컨택 예정) | 준비금, 유동성, 환매의 경제적 해석, 공시 항목 필요성 | 공시안 1쪽과 항목별 이유 |
| 담당 고욱 교수 | 과제 범위, 평가 적합성, 발표 형식 | 문제, 결과물, 검증 방법을 담은 짧은 PPT |
| 멘토 후보 신한투자증권 김병륜 | 금융서비스 설계, 데이터 흐름, 예외 처리, 구현 범위 | 실제 보고서 한 개의 실행 결과와 질문 |

컨택과 매칭은 확정 자문 실적이 아니다. 증권 트레이딩 시스템 경력을 준비금 공시나 은행 준법 전문성으로 확대하지 않는다. 상담은 공동 개발, 법률 인증, 은행 수요 검증이 아니다. 1차 멘토링은 설계와 범위, 2차는 구현과 초기 평가와 수정안. 기록은 받은 의견 → 채택 여부와 이유 → 변경 → 확인 결과.

### 2.10 첫 10~15시간

같은 발행사의 다른 달 보고서 두 개로 시작한다. 첫 보고서의 준비금, 유통량, 기준일을 직접 확인하고 추출, 계산, 대사를 만든 뒤 두 번째 보고서에 같은 방법을 적용한다. 오류 원인을 설명하고 수정할 수 있으면 자동화 범위를 넓힌다. 파싱과 웹을 한 성공 조건으로 묶지 않아 병목을 구분한다. 시간 수치는 전부 추정이다. 원안(파서 2종, 규칙 15개, 설정 6개, 화면 2개, 자동 제안, 평가)을 1인 주 15시간으로 다 하는 것은 부담이 크므로 검증 시간을 확보하려면 기능을 줄인다.

### 2.11 완성 때 남길 증거 4개

1. 누구의 어떤 작업을 돕는지 설명하는 서비스 기획 1쪽.
2. 해외 근거, 한국 적용 가정, 선택 이유가 연결된 공시안과 화면 설계.
3. 실제 자료로 정상, 누락, 불일치를 처리하고 원문까지 확인할 수 있는 공개 웹.
4. 정확성과 사용자 이해를 확인하고 수정한 기록, 본인과 AI의 작업 범위를 설명하는 짧은 사례 문서.

교수 인증, 은행 도입, 한국 최초, GPT보다 높은 정확도는 필수 완료 조건이 아니다.

## 4. 퍼플렉시티 프롬프트

웹으로 확인할 사실은 전부 원문으로 직접 확인했다. 남은 미확인은 수업 평가 비율 하나이고 이것은 강의계획서(사용자)로만 확인된다. 퍼플렉시티에 넘길 필수 항목은 없다. 굳이 돌린다면 아래 두 개는 시간이 지나면 값이 바뀌는 항목이라 발표 직전에 한 번 더 확인할 가치가 있다. 퍼플렉시티 링크는 반드시 열어 확인한다(2026-09-05에 엉뚱한 첨부 링크 2개 경험).

P1. 한국 법안 발의 여부
```
2026년 9월 정기국회에서 디지털자산기본법(가상자산 2단계법, 스테이블코인 규율 포함) 당정 통합안 또는 정부안이 실제로 발의됐는지 확인해줘. 발의됐다면 의안번호, 대표발의 의원, 발의일, 국회 의안정보시스템(likms.assembly.go.kr) 링크를 줘. 발의 안 됐다면 가장 최근의 공식 발언(정무위원장, 금융위원장)과 날짜, 기사 링크를 줘. 은행 지분 50%+1, 준비자산 100%, 이자 지급 금지 조항이 법안 원문에 있는지 조문 번호로 답해. 추측하지 말고 확인 못 한 것은 못 했다고 써.
```

P2. OCC 최종규칙 여부
```
OCC의 GENIUS Act 이행 규정(NPRM 91 FR 10202, 2026-03-02, 의견 마감 2026-05-01)이 최종규칙(final rule)으로 관보에 게재됐는지 확인해줘. 게재됐다면 관보 인용(FR 권과 면), 게재일, federalregister.gov 링크, 그리고 §15.11(e) 월간 구성 템플릿(Table 1)이 최종안에서 유지됐는지와 바뀐 점을 답해. 아직 제안 단계면 OCC가 밝힌 최종화 목표 시점의 출처를 줘. 추측하지 말고 확인 못 한 것은 못 했다고 써.
```
