세션
2023~2026년 국내외에서 스테이블코인 발행사의 준비금 보고서(Circle, Paxos, Tether 등)를 파싱하거나 규제 요건(GENIUS Act, MiCA, 홍콩 조례)을 코드 규칙으로 만들어 판정하는 프로젝트가 있었는지 조사해줘. 범위: 학술 논문, 학위 논문, 해커톤과 공모전 출품작, GitHub 외 코드 공개(GitLab, HuggingFace), 핀테크 스타트업 제품, 규제기관이나 회계법인의 도구. 각 건마다 만든 주체, 무엇을 했는지, 파서와 규칙 엔진과 화면 중 무엇이 있는지, 링크. 검색에 쓴 질의어와 검색 날짜를 마지막에 적어줘. 못 찾았으면 "확인 범위에서 없음"이라고 쓰고 검색 범위를 명시해줘.

D. 데이터와 도구 (스레드)
D1. 공개 데이터와 API 총목록
개인이 스테이블코인 프로젝트를 만들 때 쓸 수 있는 공개 데이터와 API를 전부 조사해줘. 표로: 소스 | 제공 데이터 | 형식(API / CSV / PDF / 대시보드) | 무료 범위와 제한 | 과거 데이터 범위 | 문서 링크 | 예시 엔드포인트
범주별로:
- 시장: DefiLlama stablecoins, CoinGecko, CoinMarketCap, 업비트, 빗썸
- 온체인: Etherscan API의 USDC와 USDT 이체 조회, Dune Analytics 공개 대시보드와 쿼리, Flipside, Allium 무료 범위, Circle의 mint와 burn 공개 데이터
- 준비금: Circle, Paxos, Tether 보고서와 그것을 파싱한 제3자 데이터
- 규제: 미국 연방관보 API, EUR-Lex API, 한국 국가법령정보센터 API, 국회 의안정보 API
- 거시: FRED의 국채 금리와 MMF 데이터, 한국은행 ECOS API
- 학술 데이터셋: 스테이블코인 디페그, 거래, 뉴스 관련 공개 데이터셋(Kaggle, HuggingFace, 논문 부록)
- 사고 데이터: 디페그 사건 타임라인, 해킹과 동결 사례 데이터베이스
마지막에 "API 키 없이 바로 쓸 수 있는 것"만 따로 목록으로 뽑아줘.
E. 사례와 커리어 (스레드)
E1. 개인과 학생 포트폴리오 사례: 흔한 것 피하기
2023~2026년에 학생, 개인, 소규모 팀이 만든 스테이블코인 관련 프로젝트 사례를 조사해줘: 해커톤 수상작(ETHGlobal, Circle 해커톤, 금융권 해커톤, 국내 핀테크 공모전), GitHub 공개 프로젝트, 학위논문, 부트캠프 최종 프로젝트.
표로: 프로젝트명 | 만든 사람 유형 | 무엇을 만들었는지 한 줄 | 사용 데이터 | 결과(수상, 채용 연결 등) | 링크
그다음 분석: (1) 가장 흔한 주제 5개(예: 디페그 예측, 가격 대시보드, DeFi 이자 비교)를 빈도와 함께 (2) 드물지만 평가가 좋았던 주제 5개와 이유 (3) 은행이나 금융기관이 주최하거나 심사한 대회에서 수상한 주제의 공통점
마지막에 "은행 디지털 기획 직군 지원자가 만들면 차별화되는 주제" 3개를 근거와 함께 제안해줘. 링크 필수.
E2. 금융권 디지털 직무와 스테이블코인 역량
2025~2026년 한국 금융권(은행, 카드, 증권, 핀테크)의 디지털 기획, 디지털 전략, 신사업, 블록체인 직무 채용에서 요구하는 역량을 조사해줘.
- 은행 신입 공채와 수시 채용의 디지털 직군 공고: 직무 설명, 요구 역량, 우대 자격증(정보처리기사, SQLD, ADsP, AFPK 등), 우대 경험. 공고 원문 또는 채용 플랫폼 링크. 마감된 공고는 아카이브 링크
- 공고나 인터뷰에서 스테이블코인, 디지털자산, 토큰증권, CBDC를 직접 언급한 사례
- 2026 금융권 공동채용박람회 참가 은행의 디지털 직무 설명
- 은행 디지털 부서 현직자 인터뷰나 강연에서 "신입에게 기대하는 프로젝트 경험"을 말한 내용
- 금융권 디지털 직군 자기소개서에서 프로젝트를 서술하는 방식의 합격 사례(공개된 것)
공고는 원문 URL, 인터뷰는 매체 링크. 확인 안 되는 건 "확인 불가"로.
C4. 예금 이탈과 은행 재무 영향
스테이블코인 확산이 은행 예금과 수익에 주는 영향을 정량적으로 다룬 공식 보고서를 조사해줘.
- 미국 재무부(2025 스테이블코인 보고서, TBAC 자료), 연준, FDIC, BIS, IMF, ECB의 보고서: 예금 이탈 추정치, 국채 수요 추정치, 시나리오 가정. 보고서 링크와 해당 페이지
- 미국 은행협회(ABA), 지역은행 단체가 GENIUS Act 논의 때 제출한 의견서의 예금 이탈 주장과 수치
- 학술 논문: 스테이블코인과 은행 예금의 대체 관계를 실증한 논문 2~3편, 데이터와 결과
- 한국 적용 재료: 국내 은행 요구불예금 잔액과 금리(한은 통계 코드), 은행별 저원가성 예금 비중(사업보고서), 한국은행이 언급한 예금 이탈 우려 문서
- 반론: 예금토큰이나 은행 발행 스테이블코인이면 이탈이 아니라는 주장의 근거
수치마다 값, 가정, 기준 시점, 출처를 표로. 원문 링크 필수.
F. 리스크 (스레드)
F1. 디페그와 런 사례, 은행 리스크 관리 시사점
스테이블코인 디페그와 뱅크런 사례를 타임라인으로 정리하고 은행 리스크 관리 관점의 시사점을 뽑아줘.
- 사례: Terra UST 2022-05, USDC의 SVB 노출 2023-03, USDT 2022-05 일시 디페그, 그 외 2024~2026년 사례
- 사례마다 표로: 날짜와 시각 | 원인 | 최저 가격 | 회복까지 시간 | 환매 규모 | 발행사와 규제기관 대응 | 공시가 있었다면 시점 | 출처
- 각 사례에서 "정보 공백"이 있었던 구간: 준비금 상태를 몰라서 공포가 커진 시간, 공식 발표 전 소문이 퍼진 시간
- 규제기관이 사례 뒤에 바꾼 규정(공시 주기, 준비자산 제한)
- 은행이 스테이블코인을 발행하거나 취급할 때 적용되는 리스크 관리 프레임: BIS 바젤위원회의 암호자산 익스포저 기준(2025 시행), 미국 은행 감독기관 지침, 한국은행 금융안정보고서의 언급
- 온체인 데이터로 디페그를 조기에 볼 수 있었던 신호(대량 환매, 거래소 잔고 급증)와 그것을 보여주는 공개 대시보드
원문과 데이터 링크 필수. 시각은 UTC로 통일.
C3. 실시간 정산 시뮬레이터 재료
스테이블코인 기반 가맹점 실시간 정산과 기존 카드 정산을 비교할 수 있는 공개 데이터를 조사해줘.
- 한국 카드 결제의 가맹점 정산 주기(승인 → 매입 → 입금)와 단계별 소요일, 가맹점 수수료율 구간(영세, 중소, 일반), 밴사와 PG 수수료. 여신금융협회, 금융위 자료 링크
- 배달앱(쿠팡이츠, 배민)의 가맹점 정산 주기와 선정산 서비스 수수료 공개 자료
- 쿠팡-우리은행 PoC의 정산 흐름: 주문 → 결제 → 스테이블코인 전송 → 가맹점 지갑 → 은행 계좌 오프램프. 공개된 구조도
- 해외 사례의 정량 효과: Visa와 Stripe의 USDC 정산, JPMorgan Kinexys의 정산 시간 단축 수치, 국경간 정산 비용 절감 수치. 회사 공식 발표 링크
- 은행 입장의 손익 요소: 정산 대금이 예금으로 머무는 기간(float)과 그 이자 수익, 스테이블코인 정산 시 은행이 받을 수 있는 수수료 모델, 예금 이탈 추정
- 온체인 정산의 실제 비용: Ethereum L2와 Solana에서 USDC 전송 수수료와 확정 시간(2026년 기준)
시뮬레이션 변수로 쓸 수 있게 각 수치에 값, 단위, 기준 시점, 출처를 표로 정리해줘.
C2. 은행 앱 온오프램프 UX
은행 앱 안에서 법정화폐와 스테이블코인을 전환하는 온오프램프 서비스의 실제 사례와 규제 체크포인트를 조사해줘.
- 은행이 직접 제공하는 사례: 어느 은행이, 어떤 화면 흐름(가입, 지갑 개설, KYC, 환전, 한도, 출금, 환매)으로, 공개된 화면 캡처나 데모 영상 링크. 은행이 없으면 규제받는 핀테크(Revolut, Nubank, PayPal PYUSD, Coinbase) 사례
- 쿠팡-우리은행 2026-07 PoC에서 우리은행이 맡은 전자지갑과 계좌 연동의 구체 내용
- 홍콩 조례와 일본 자금결제법에서 은행이 이용자에게 판매 또는 환매할 때의 의무(KYC, Travel Rule, 한도, 설명 의무, 적합성)
- 한국 전자금융거래법, 특정금융정보법, 자본시장법에서 은행이 같은 서비스를 하려면 걸리는 조항과 필요한 등록 또는 인가
- 이용자 보호 화면 요건: 환매 가격 표시, 준비금 상태 표시, 리스크 고지 문구를 규제가 요구한 사례
- 세금: 한국에서 스테이블코인 환전 차익 과세 여부와 은행의 원천징수 의무 논의
각 항목마다 원문 링크. 화면 흐름은 단계 | 사용자 행동 | 은행 처리 | 규제 체크 | 근거 형식의 표로.
A. 지형 파악 (스레드 1)
A1. 은행이 실제로 만든 스테이블코인 프로젝트 지도
2024~2026년에 은행이나 은행 계열사가 실제로 만들거나 시범 운영한 스테이블코인 관련 프로젝트를 미국, EU, 영국, 홍콩, 일본, 싱가포르, UAE, 한국별로 조사해줘.
프로젝트마다 표로: 은행명 | 프로젝트명 | 유형(직접 발행 / 예금토큰 / 수탁 / 정산 / 온오프램프 / 준비금 관리 / 국경간 송금 / 컨소시엄 참여) | 상태(시범 / 상용 / 중단) | 규제 근거 | 은행 공식 발표 링크 | 기술 또는 화면 자료 링크
꼭 포함: Société Générale Forge EURCV, JPMorgan Kinexys와 JPM Coin, Citi Token Services, Standard Chartered와 HKMA 샌드박스, 일본 MUFG Progmat와 SBI, 싱가포르 DBS, 미국 은행 컨소시엄(JPMorgan, BofA, Wells Fargo 등이 논의한 공동 스테이블코인), Bank of America의 자체 발행 검토, 한국 KB 신한 우리 하나 NH.
마지막에 두 가지 판단을 표로: (1) 은행이 직접 발행과 예금토큰 중 어느 쪽으로 가는 추세인지, 근거 3개 (2) 각 프로젝트 중 개인이 공개 데이터로 일부라도 재현하거나 벤치마킹할 수 있는 것.
은행 공식 발표나 규제기관 자료를 우선하고, 언론 보도만 있으면 그렇게 표시해줘. URL은 전체로.
A2. 스테이블코인 밸류체인에서 은행의 자리
스테이블코인 밸류체인을 단계별로 분해하고 각 단계에서 은행이 할 수 있는 역할과 실제 사례를 조사해줘.
단계: 발행 → 준비금 보관과 운용 → 수탁 → 유통(거래소, 지갑) → 결제와 정산 → 온오프램프 → AML과 제재 스크리닝 → 공시와 감사 → 환매와 청산.
단계마다 표로: 핵심 플레이어(비은행) | 은행이 맡은 실제 사례 | 은행이 얻는 수익 또는 잃는 것(수수료, 예금, 결제 수익) | 규제상 은행만 할 수 있거나 은행이 유리한 지점 | 출처
특히 미국 GENIUS Act와 EU MiCA에서 은행 또는 은행 자회사에만 허용되거나 은행에 유리한 조항이 있으면 조문 번호와 함께 표시해줘.
마지막에 "한국 은행 컨소시엄 모델에서 은행이 반드시 직접 해야 하는 단계"를 근거와 함께 골라줘. 원출처 링크 필수.
C. 후보 심화 (후보당 스레드 하나)
C1. 준비금 투명성 공시 설계
스테이블코인 준비금 공시의 규제 요건과 실제 공시 형식을 조사해줘.
- 미국 GENIUS Act의 준비금 공시 의무: 공시 주기, 공개 항목(자산 종류별 금액, 만기, 수탁기관), 검증 주체와 검증 수준(examination인지 audit인지), 시행 시점. 조문 번호와 원문 링크
- EU MiCA EMT 준비자산 규정: 은행 예치 비율, 허용 자산, 공시 의무, 조문 번호
- Circle USDC 월간 examination report와 Paxos PYUSD 월간 보고서의 실제 구성: 표와 항목 전체, 최근 2개월치 PDF 링크
- Tether 분기 보고서와 위 둘의 차이
- 준비금 공시를 기계가 읽을 수 있는 형식(JSON, XBRL, API)으로 제공하는 발행사나 제3자(DefiLlama, Bluechip 등)가 있는지
- 준비금 공시의 실패 사례: Tether 2021 벌금, USDC 2023 SVB 노출 공시 시점, 그 뒤 바뀐 관행
- 한국 금융위나 한국은행이 원화 스테이블코인 준비금 공시에 대해 언급한 공식 문서
목표는 "원화 스테이블코인 준비금 공시 화면"을 설계하는 것이니, 각 요건을 화면 항목(무엇을, 어떤 주기로, 어떤 검증 표시와 함께)으로 옮길 수 있게 표로 정리해줘. 원문 링크 필수.
B. 규제 (스레드 2)
B1. GENIUS Act 조문 단위 요구사항
미국 GENIUS Act(2025년 7월 제정)의 발행사 요구사항을 조문 단위로 정리해줘.
표로: 조문 번호 | 요구사항 한 줄 | 대상(모든 발행사 / 은행 자회사 / 비은행 / 해외 발행사) | 세부 내용(준비금 자산 종류, 비율, 공시 주기, 검증 주체, 환매 기한, 자본, AML) | 시행 시점 | 하위규정 제정 상태(2026년 9월 기준: 제안 / 의견수렴 / 최종)
꼭 포함: 준비금 1:1 요건과 허용 자산 목록, 월별 공시와 회계법인 검증 요건, 환매 요건, 은행 자회사 발행 경로와 OCC 인가, 주 규제 대 연방 규제 경계(100억 달러 기준), 해외 발행사 취급, 파산 시 보유자 우선권, 이자 지급 금지 여부.
그다음 재무부, OCC, FinCEN, FDIC가 2025~2026년에 낸 하위규정 제안을 날짜순으로 표로 정리하고 각각 연방관보 링크를 붙여줘.
마지막에 "한국 정부안에 그대로 옮겨질 가능성이 높은 조항 5개"를 근거와 함께 골라줘. 법 원문은 congress.gov 또는 govinfo 링크로.
B2. 은행 중심 발행 규제 비교: 홍콩, 일본, 싱가포르, EU
은행이 스테이블코인 발행에 참여하는 구조를 가진 관할권의 규제를 비교해줘: 홍콩 스테이블코인 조례(2025-08 시행), 일본 자금결제법(2023 개정, 은행과 신탁이 발행), 싱가포르 MAS 단일통화 스테이블코인 프레임워크(2023), EU MiCA EMT 조항.
표로: 항목 | 홍콩 | 일본 | 싱가포르 | EU

① 데이터 정당성 — 지금 제일 찜찜해하는 부분

내 상황: 52일간 자체 수집한 기사 310건, 추출 주장 697건, AI 잠정 라벨 + 사람 골드셋 50건으로 검증 예정. 이 규모가 유사 연구 대비 어느 정도인지 비교해줘.

범주별 판단
1. 준비금 보고서 파싱
가장 직접적인 사례는 Xiang 외의 2025년 프리프린트입니다. 논문은 발행사의 비정형 공시·attestation 자료를 파싱해 자산·부채 등 재무지표를 추출하고, 이를 온체인 지표와 연결합니다. 단순 OCR이나 표 추출을 넘어서, 공시와 온체인 발행량의 의미적·시간적 정렬을 목표로 한다는 점에서 질문의 “보고서 파싱 + 판정”에 가장 가깝습니다. 다만 논문 페이지에서 별도의 공개 소스코드·데모 UI 링크는 확인되지 않았습니다.web3.arxiv
Veris는 상용 문서상 발행사 피드와 온체인 proof 메커니즘에서 준비금 attestation을 가져와 공급량과 검증·모니터링하므로, 운영 제품 관점에서 가장 가까운 사례입니다. 그러나 Circle·Paxos·Tether의 원본 PDF를 어떤 방식으로 파싱하는지, 추출 필드의 정확도·출처·재현 가능한 코드가 공개되어 있지는 않습니다.docs.useveris
The Network Firm의 도구는 발행사가 직접 제공하는 은행·수탁기관·체인 API를 통합하는 실시간 PoR 감사 인프라입니다. 즉, 사후적으로 공개된 Tether/Circle/Paxos PDF를 읽는 크롤러보다는 원천 데이터 연결형 시스템에 가깝습니다.thenetworkfirm
2. 규제 요건의 코드화
MiCA는 FeedOracle에서 가장 명시적으로 코드화되어 있습니다. 문서에 따르면 mica_status, mica_full_pack, significant_issuer, interest_check, document_compliance, reserve_quality, peg_deviation 같은 도구가 제공됩니다. 특히 준비금 적격성·유동성은 MiCA 제24·25·53조, 중요 발행사 판단은 제45·58조, 이자 금지는 제23·52조 등으로 조문 범위가 문서화돼 있습니다. 이는 “규제 요건 → 조건/체크 → 결정값” 구조의 공개된 사례입니다.feedoracle
MicaUSD는 MiCA “컴플라이언트”를 표방하지만, 실제로는 MiCA의 인가·백서·상환권·준비금 구성·운영거버넌스 등 모든 법률요건을 완전하게 조문별 판정하는 엔진이라기보다, 규제 친화적 구성요소를 스마트계약에 녹인 프로토타입입니다. 따라서 규칙 엔진으로 분류하되, 법률 컴플라이언스 판정도구로 해석하면 안 됩니다.github
GENIUS Act는 2025년 제정되어 준비금 분리, 월별 준비금 구성 공시·회계법인 검토 등의 법적 골격이 존재합니다. 다만 이번 확인 범위에서는 이를 상세한 공개 코드 규칙, 오픈 API 또는 조문별 판정표로 구현한 프로젝트를 찾지 못했습니다. Rizkly는 해당 법 준수관리 제품을 표방하지만 공개된 세부 구현 증거는 부족합니다.congress+1
홍콩의 Stablecoins Ordinance는 2025년 8월 1일부터 시행되어 법정화폐 연동 스테이블코인 발행에 라이선스 체계를 적용합니다. 그러나 공개적으로 검증 가능한 형태의 “홍콩 조례 판정 엔진” 또는 “준비금 보고서 파서와 연결된 조례 체크리스트 코드”는 이번 범위에서 확인하지 못했습니다.hkma.gov+1
확인 범위에서 없음
다음은 확인 범위에서 없음으로 정리합니다. 이는 존재하지 않는다는 단정이 아니라, 아래 명시한 웹·공개 저장소 중심 조사에서 검증 가능한 결과를 찾지 못했다는 뜻입니다.
Circle, Paxos, Tether의 공개 준비금 보고서를 정기적으로 수집·PDF/HTML 파싱하고, 동일 데이터 모델로 표준화해 비교하는 2023~2026 공개 GitHub/GitLab/Hugging Face 프로젝트.
GENIUS Act 전체 또는 핵심 조항을 공개 소스코드의 명시적 규칙으로 구현해 pass/fail을 판정하는 프로젝트.
홍콩 Stablecoins Ordinance 또는 HKMA 발행사 규제 가이드라인을 조문별 머신리더블 규칙으로 구현한 공개 프로젝트.
이 주제를 직접 대상으로 한 국내 대학 학위논문, 국내 해커톤·공모전 출품작, 국내 규제기관·국내 회계법인의 공개 도구.
GitLab 또는 Hugging Face에서 “Circle/Tether/Paxos reserve-report parser”로 식별 가능한 공개 코드·데이터셋.
이 공백에는 이유가 있습니다. 원본 보고서가 월별·분기별 PDF, 웹페이지, 수탁기관 데이터, 감사확인서 등 여러 형식으로 산재해 있고, 법률상 준수 판단은 관할·발행사 분류·인가상태·운영 사실에 따라 달라집니다. 그래서 공개 생태계에서는 범용 파서보다 온체인 PoR, 리스크 스코어링, MiCA 인가상태 조회 쪽이 상대적으로 많이 확인됩니다.
법·프로젝트 해석 유의점
MiCA: 스테이블코인 관련 규정은 2024년 6월 30일부터 적용되었으며, 인가·준비금·상환·공시·운영 의무는 토큰의 EMT/ART 분류와 발행사 상태에 따라 달라집니다. 따라서 “MiCA compliant”라는 제품 문구만으로 실제 법적 준수를 의미하지는 않습니다.scorechain
GENIUS Act: 법률상 월말 준비금 구성 공개와 등록 공인회계법인에 의한 검토 등 요건이 핵심이지만, 세부 시행규칙·감독기준에 따라 코딩 가능한 필드 정의가 더 구체화될 필요가 있습니다.congress+1
홍콩: Stablecoins Ordinance는 2025년 8월 1일 시행됐고 라이선스가 필요한 발행행위를 정의합니다. 실제 엔진화에는 법령뿐 아니라 HKMA의 시행 가이드·라이선스 기대수준까지 함께 반영해야 합니다.hkma.gov+1
감사·attestation의 한계: attestation은 특정 기준일의 준비금·부채에 대한 제한된 검증일 수 있으며, 전면감사나 미래 유동성·상환능력 보증과 동일하지 않습니다. 그래서 도구 설계 시 “준비금 비율” 외에도 기준일, 발표지연, 자산 구성, 수탁·분리보관, 감사인·검토기준을 별도 필드로 보아야 합니다.thenetworkfirm
