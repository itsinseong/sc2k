### 문서 간 불일치 (실측으로 확인됨 — 사용 전 반영 권고)

1. **트리비얼 최종 건수**: `정제결과_요약.md`는 QC 정정 후 최종 187건(26.8%)·유효 510건이라 기재하나, 실제 `archive_copy.db.claims_typed`/`claims_typed.csv`는 190건(27.3%)·유효 507건이다. 문서가 언급한 2차 QC 정정 3건(id 42, 197, 340 — 파편/동어반복 오분류) 중 이 3건은 `trivial=1`로 남아 있어 **데이터에 미반영**됨을 직접 확인했다(1차 정정 4건 id 377/383/417/495만 반영됨). SW-PL-02 착수 시 이 3건을 실제로 `trivial=0`으로 갱신하거나, 문서의 187건 기재를 190건으로 정정해야 한다.
2. **수집 기간**: PRD 2절은 "85일 수집 기준", 4절은 "2026-05-30부터 약 3개월 운영"이라 하나, **원본** `archive.db`의 `articles.fetched_at` 실측 범위도 2026-06-03~2026-07-25로 **52일**이다(사본과 완전 일치 — 사본 절단 가능성은 배제됨). 즉 5월 데이터 부재·8월 공백은 사본 생성 과정의 문제가 아니라 원본 DB 자체의 실제 수집 이력이다. PRD의 "85일"/"3개월"은 원본 DB로 뒷받침되지 않는 수치이므로 발표·문서에서 52일로 정정해야 하며, 6/3 이전·7/25 이후 수집이 왜 끊겼는지(스케줄러 중단? 소스 변경?)는 여전히 원인 미확인 — SW-PL-05/06 착수 전 확인 필요 항목으로 유지.
3. **"한국 고신뢰 약 5건"의 기준값**: PRD 9절 표현이 정확히 맞아떨어지는 것은 confidence **≥0.9** 기준일 때뿐이다(5건). confidence≥0.8로 완화하면 40건으로 8배 뛴다. 백로그/리포트(SW-RP-03)에서 "고신뢰" 임계값을 0.9로 명시하지 않으면 발표 중 수치가 뒤집힐 위험이 있다.

### SW-PL-03 수동 골드셋 재검증(30~50건) [미착수] — P0 · 3일

**목적** 파이프라인 판정과 사람 판정의 불일치율을 실측해 "신뢰도 0.6 집중=미보정" 주장에 근거를 대고, SW-RP-02(AI 오판 3유형)의 원재료를 만든다.

**입력** `claims`(697건, confidence·verdict) + `claims_typed`(type·trivial) — 신뢰도 구간(0.2/0.4/0.5/0.6/0.7/0.8/0.9대) × 판정(supported/uncertain/contradicted)으로 층화 추출.

**처리 흐름** 층화 추출 30~50건 선정 → 각 건 원문 기사(articles.link) 대조 → 사람 판정 기록 → 파이프라인 판정과 나란히 표로 정리 → 불일치 사유 분류.

**출력** 골드셋 표(주장ID·파이프라인 판정·사람 판정·불일치 사유) — 신규 테이블 또는 CSV.

**예외 처리** `contradicted` 18건은 표본에 전건 포함 권장(SW-RP-02가 이 18건을 그대로 쓰므로 재검증 없이 넘기면 화면4 근거가 얕아짐).

**Acceptance Criteria**
- 30~50건 사람 재판정 결과가 파이프라인 판정과 나란히 표로 기록됨

- 불일치 건수·사유 정리됨
- 결과가 SW-RP-02 입력으로 연결됨

**의존 데이터** `archive_copy.db.claims`(confidence, verdict), `archive_copy.db.articles`(link, 원문 대조용), `claims_typed`(층화 기준).

### SW-VF-01 5단계 판정 게이트 로직 [미착수] — P0 · 4일

**목적** "판정 규칙은 코드, LLM은 대조·요약만"이라는 설계 원칙을 실제 동작 코드로 증명한다.

2. 교차보도 ≥2건(동일 사건 복수 article_id) + confidence 임계값 이상 → **복수 보도 확인**

4. type='예정형' → **예정·미확정**

**예외 처리** 어느 규칙에도 안 걸리면(예: 수치형인데 대조 실패) 다음 낮은 등급으로 폴백하되, LLM이 등급을 직접 결정하지 않는다는 경계를 코드 구조로 강제(등급 결정 함수에 LLM 호출 자체가 없어야 함).

**Acceptance Criteria**
- 5등급 각각 코드 규칙 존재(LLM 호출 없이 등급 결정 가능)
- 동일 입력 반복 실행 시 동일 등급(비결정성 없음)
- 최소 10건 샘플에 대해 사람 검수 일치율 보고
- LLM 관여 지점(대조·요약)과 비관여 지점(등급 결정)이 코드 구조상 분리

**의존 데이터** `archive_copy.db.claims`(confidence, verdict), `claims_typed`(type), SW-PL-09 대조 결과.

## 에픽 6. 데이터 분석 리포트(화면4)

### SW-RP-01 매체별 판정·신뢰도 분포 분석 [부분완료 — 원재료만] — P0 · 2일

**목적** "신뢰도 0.6에 43% 집중=미보정"이 이 프로젝트 분석력의 핵심 근거이며, 매체별 판정 분포는 어느 코인 매체가 신뢰하기 어려운지 정량 지목한다.

**입력** `claims` JOIN `articles`(source) — 매체×판정×신뢰도 구간 교차.

**처리 흐름** SQL 집계(`GROUP BY source, verdict` / 신뢰도 구간별 카운트) → 차트 렌더(막대 또는 히트맵으로 0.6 집중 강조).

**출력** 매체별 분포 표/차트, 신뢰도 히스토그램.

**예외 처리** 표본이 적은 매체(BeInCrypto 5건, Blockworks 1건 등)는 비율 대신 절대 건수 병기(비율만 보여주면 과장 위험).

**Acceptance Criteria**
- 매체별 판정 분포 조회 가능
- 신뢰도 0.6 구간 집중이 수치로 확인(**실측: 42.9%, 299/697건 — 이미 확정됨**)
- 오보 경향 매체 최소 1곳 식별(contradicted 비율 기준 SQL로 산출 필요, 미착수)
- 화면4에 실제 렌더링

**의존 데이터** `archive_copy.db.claims`, `articles.source`. 실측 원재료(verdict 분포·0.6 집중 수치)는 본 문서 0절에 이미 확보됨 — 남은 일은 매체별 교차 집계와 화면 렌더.

### SW-RP-02 AI 오판 3유형 정량화 [미착수] — P0 · 2일

**목적** contradicted 18건을 "시간축 혼동/사전지식 우선/출처 신뢰 오판" 3유형으로 라벨링해 AI 한계를 스스로 짚는 분석력을 보여준다 — 발표에서 가장 설득력 있는 슬라이드 후보.

**입력** `claims WHERE verdict='contradicted'`(실측 18건) + SW-PL-03 골드셋 결과.

**처리 흐름** 18건 원문 대조 → 3유형 중 라벨링(복수 태깅 가능 여부는 착수 시 결정) → 유형별 건수·대표 사례 정리.

**출력** 유형별 건수 표 + 사례 카드(화면4·발표자료 SW-OP-03 공용).

**예외 처리** 3유형 어디에도 안 맞는 사례가 나오면 "기타"로 분리하고 임의로 끼워 맞추지 않는다.

**Acceptance Criteria**
- 18건 전체가 3유형 중 하나 이상으로 라벨링
- 유형별 건수 집계, 최다 유형 확인
- 유형별 사례 최소 1건 근거 제시
- 화면4·SW-OP-03 양쪽 재사용 가능한 형태로 정리

**의존 데이터** `archive_copy.db.claims`(contradicted 18건, 실측 확인 완료).

### SW-RP-03 한/영 매체 프레이밍 비교 + 주장 유형 비율 [미착수] — P1 · 2.5일

**목적** 국내외 매체가 같은 사건을 다르게 포장하는 패턴을 정량으로 보여줘 "왜 검증이 필요한가"의 설득력을 더한다.

**입력** `articles.lang`(en 222 / ko 88) × `claims_typed.type` 교차.

**처리 흐름** 언어별 표현 차이(예: "검토"vs"확정" 빈도) 비교 → 유형 비율 차트(`정제결과_요약.md` 3절 원재료: 한국어는 수치형 28.5% vs 영어 10.7%, 영어는 사건형 56.0%·예정형 11.9%로 더 높음 — 이미 실측 완료).

**출력** 언어별 프레이밍 비교 섹션 + 유형 비율 차트.

**예외 처리** "고신뢰" 등 임계값을 쓰는 비교(예: 한국 고신뢰 주장 수)는 confidence≥0.9로 통일 표기(불일치③ 반영 — 0.8 기준과 혼용 금지).

**Acceptance Criteria**
- 한국/영어권 매체 판정·표현 경향 비교됨
- 최소 1개 사건에 대해 프레이밍 차이 사례 제시
- 유형별 비율 차트로 조회 가능(원재료 실측 완료: 위 참조)
- SW-RP-01과 구분된 섹션으로 화면4에 노출

**의존 데이터** `archive_copy.db.articles.lang`, `claims_typed.type`(정제결과_요약.md 3절에 원재료 존재).

## 에픽 7. 운영·발표

### SW-OP-01 Vercel 자동 배포 파이프라인 [미착수] — P0 · 2일

**목적** 매일 갱신되는 데이터가 실제 배포 화면에 반영되지 않으면 "데일리 브리핑"이라는 이름이 무색해진다.

**입력** python 파이프라인 산출물(갱신된 `archive.db` 또는 API 응답).

**처리 흐름** 정적 빌드 재생성(예약 재배포) vs 런타임 조회(API가 DB 직접 읽음) 중 방식 결정 → Vercel 연동.

**출력** 매일 갱신되는 배포 화면.

**예외 처리** 배포 실패 시 이전 정상 버전 유지(서비스 중단 없음).

**Acceptance Criteria**
- 매일 1회 이상 무개입 배포/갱신
- 배포 화면 데이터가 최신 DB와 일치
- 배포 실패가 서비스 중단으로 이어지지 않음
- 배포 이력 확인 가능

**의존 데이터** 원본 `archive.db`(SW-PL-05 갱신분).

### SW-OP-02 발표용 데모 시나리오 [미착수] — P0 · 2일

**목적** "삼성 발행 확정?" 류 질의에 30초 안에 근거 기반으로 답하는 장면이 제품 가치를 가장 압축적으로 보여준다.

**입력** 화면3(SW-VF-01/02/03) 완성 상태.

**처리 흐름** 질의→판정→근거 제시 시연 스크립트 작성 → 실제 화면으로 최소 2회 리허설 → 실패 대비 백업(녹화본) 준비.

**출력** 시연 스크립트 문서 + 백업 녹화본.

**예외 처리** 라이브 데모 실패(네트워크/API 쿼터/매칭 실패) 시 즉시 녹화본으로 전환.

**Acceptance Criteria**
- 질의→근거 제시 소요 시간 30초 내외 측정
- 최소 2회 실제 화면 리허설
- 라이브 실패 시 대체 수단 준비
- 시나리오 대본 문서화·공유 가능

**의존 데이터** 화면3 전체(SW-VF-01/02/03), 데모용 질의 샘플(예: 위 SW-VF-01 게이트 예시).

### SW-OP-03 기획서 발표 자료 [미착수] — P0 · 2일

**목적** 4~6주차 기획서 발표는 학기 방향을 검증받는 첫 체크포인트.

**입력** 문제 정의(노이즈·과장), 기반 자산(파이프라인·697건 분석), 4개 화면 컨셉, 남은 일정.

**처리 흐름** 슬라이드 구성 → 이미 증명한 것(0절 실측 수치)과 개발할 것(화면 4종) 구분 제시 → 리허설.

**출력** 발표 슬라이드 세트.

**예외 처리** 발표 시간 제한 확인 안 됨(PRD 미확인 목록) — 확인 전까지 15분 기준 초안으로 작성 후 조정.

**Acceptance Criteria**
- 문제 정의(노이즈 30~40%, 과장 사례)가 근거와 함께 포함
- 기존 확보 자산(파이프라인, archive.db 통계)이 동작 증거로 제시
- 4개 화면 컨셉·우선순위가 로드맵 형태로 제시
- 발표 시간 내 리허설 완료

**의존 데이터** 본 문서 0절 실측 스냅숏 전체, `정제결과_요약.md`.
