## 1. 한 줄 정의

은행 디지털자산 TF·컴플라이언스 담당자가 코인 매체 동향을 보고서에 올리기 전, 검증된 사실만 근거와 함께 골라주는 인텔리전스 도구.

## 2. 문제 정의

근거를 신뢰 수준이 다른 3층으로 나눈다.

**① 시장 사실(확인됨)** — KB국민·신한·우리·NH농협 등 8개 은행이 스테이블코인 공동 발행 컨소시엄을 구성했고, KB는 그룹 협의회 내 스테이블코인 분과를 상설화했다(파이낸셜투데이[1], 이포커스[2]). 카드사 9곳도 TF를 꾸리고 공동 상표 30건을 출원했다(헤럴드경제[3]). 은행권의 관심이 검토 단계를 넘어 조직·상표 등록 단위로 구체화되고 있음을 보여준다.

**② 자체 실측(archive.db, 52일 수집 실측 기준)** — 코인 매체 기사의 30~40%가 주제와 무관한 노이즈였고, 동일 사건에 반대 방향으로 보도된 사례가 존재했으며, AI 자동 요약의 명백한 오판이 18건 확인되었다. 즉 원본 코인 매체 기사를 그대로 보고서에 인용하는 현재 방식은 노이즈 제거와 교차검증을 전적으로 사람의 판단에 의존하고 있다. (수집 기간은 PRD 기재 "85일"이 아니라 실측 52일 — §6 불일치② 참조)

**③ 업계 신호(확인됨)** — 2026 금융권 공동채용 박람회 공식 세션으로 "AI Agent 시대, 일하는 방식의 변화와 금융업 필요 역량"이 편성되었다(financejobfair.co.kr[4]). 은행연합회는 8/20 FRC 2026에서 "금융권 AI, 속도보다 통제"를 주제로 다뤘다(디지털데일리[5]). 금융권이 AI 활용 확대와 동시에 통제 가능성을 요구하는 국면이라는 신호로 읽힌다.

세 층을 종합하면, 은행권의 스테이블코인 대응 조직화(①)가 빠르게 진행되는데 정보 소스(코인 매체)는 검증 부담이 크고(②), 금융권은 AI를 쓰되 통제된 형태를 요구한다(③)는 간극이 이 제품의 존재 근거다.

## 3. 타깃·페르소나

| 순위 | 페르소나 | 핵심 니즈 |
|---|---|---|
| 1차 | 은행 디지털자산 TF 실무자 | 동향 보고서에 올릴 검증된 사실 확보 |
| 2차 | 컴플라이언스 담당자 | 부정 뉴스·제재 리스크 스크리닝 |
| 3차 | 스테이블코인 학습자 | 규제·시장 현황 학습 |

TF는 임시조직이라는 반문에 대한 방어선: KB가 이미 분과를 **상설화**했고(§2 ①) 카드사가 상표 30건까지 출원한 만큼, 은행권은 지금 TF→상설 조직 전환기다 — 그 전환 자체가 이 시장이 일회성 검토가 아니라는 증거. 2차 페르소나(컴플라이언스)는 애초에 상설 기능 부서라 임시성 문제가 없다.

## 4. 핵심 가치·차별점

**(a) 실데이터 자산** — 자체 운영한 파이프라인(collector→analyst→critic→synthesizer, Gemini+Groq 폴백)의 산출물로, 기사 310건 전체가 원문 URL을 보유하고 697건 주장에 검증 메타데이터가 붙어 있다. 수집 실측 기간은 2026-06-03~07-25의 52일(§6 불일치② — PRD의 "5/30부터 약 3개월"은 실측으로 뒷받침되지 않아 정정).

**(b) 5단계 판정** — 참/거짓 2단계가 아니라 "수치로 확인됨 / 복수 보도 확인 / 단일 보도 / 예정·미확정 / 의견"의 5단계로 나눈다. 검증 불가능한 것(예정, 의견)을 확인된 것처럼 말하지 않는 설계다.

**(c) 모델 리스크 자기 공개** — AI 오판 18건을 감추지 않고 리포트 화면에서 유형화해 보여준다. "AI를 쓰되 통제한다"는 금융권 요구(§2 ③)에 정면으로 부합하는 차별점이다.

### 문서 간 불일치 3건 — 실측 확인, 화면 개발 전 반영 필요

1. **트리비얼 최종 건수**: `정제결과_요약.md`는 QC 정정 후 최종 187건(26.8%)·유효 510건이라 기재하나, 실제 `claims_typed` 테이블·CSV는 **190건(27.3%)·유효 507건**. 문서가 언급한 2차 QC 정정 3건(id 42·197·340 — 파편/동어반복 오분류)이 `trivial=1`로 남아 데이터 미반영(1차 정정 4건 id 377/383/417/495만 반영됨). SW-PL-02 착수 시 3건을 `trivial=0`으로 갱신하거나 문서 기재를 190건으로 정정할 것.
2. **수집 기간**: PRD는 "85일 수집"·"5/30부터 약 3개월"이라 했으나 원본 `articles.fetched_at` 실측 범위는 2026-06-03~07-25의 **52일**(사본 절단 아님 — 원본도 동일). 5월 부재·8월 공백은 원본 DB의 실제 수집 이력. 발표·문서는 52일로 통일(본 문서는 정정 반영 완료). 6/3 이전·7/25 이후 수집이 끊긴 원인은 미확인 — SW-PL-05/06 착수 전 확인.
3. **"한국 고신뢰 약 5건"의 기준값**: confidence **≥0.9**일 때만 정확히 5건. ≥0.8로 완화하면 40건으로 8배 뛴다. 리포트(SW-RP-03)·발표에서 임계값 0.9 명시 고정 — 0.8 기준과 혼용 금지.

## 7. 검증 5단계 체계

| 등급 | 판정 방법 | 데이터 소스 | 한계 |
|---|---|---|---|
| 수치로 확인됨 | 주장 속 수치를 시장 데이터와 코드로 자동 대조해 일치 확인 | 시장 API(DefiLlama·CoinGecko·업비트/빗썸) | 자연어에서 종목·시점·수치 추출이 어려운 경우 자동 매칭 실패 → 병치 표시로 폴백(등급 하향) |
| 복수 보도 확인 | 교차보도 건수(≥2)·신뢰도 임계값을 코드 규칙으로 게이팅 | 뉴스 아카이브(archive.db) | 동일 소스 재인용을 디듀프하지 못하면 복수 보도로 오인될 수 있음 |
| 단일 보도 | 교차보도 1건, 신뢰도 임계값 이상 | 뉴스 아카이브 | 단일 출처 오보 가능성이 그대로 남음 |
| 예정·미확정 | 주장 유형 분류(예정형) + 1차 사료 대조 결과 부재 | 뉴스 아카이브 + 1차 사료 RSS(SW-PL-04, P1) | 1차 사료 연동 전에는 "검토중→확정 둔갑" 오탐 방지가 규칙 기반에만 의존 |
| 의견 | 주장 유형 분류에서 의견형으로 태깅 | 뉴스 아카이브 | 의견과 사실이 섞인 문장의 경계는 규칙만으로 애매할 수 있음(SW-PL-01) |

판정 등급은 코드 규칙으로 결정론적으로 게이팅하고, LLM은 후보 근거 수집·요약에만 관여한다(SW-VF-01의 설계 원칙 — 구체 게이팅 규칙은 §9 SW-VF-01).

**목적** "걸러진 것도 투명하게 보여준다"는 태도 — 다른 자동 요약 도구와 구분 짓는 지점. SW-PL-02 산출물을 실사용자에게 노출.

**입력** `claims_typed`(trivial=1, trivial_reason).

**처리** 당일(또는 최근 배치) 건수·사유별 집계 → 카드 피드(SW-BR-01) 통과 건수와 합산 검증 → 패널 렌더(총 건수 + 사유별 분해: 동어반복/파편/주제외).

**예외** 통과+걸러짐 합이 전체 처리 건수와 불일치하면 표시하지 않고 로그만 남김(잘못된 합계를 사용자에게 보여주지 않음).

**AC** 당일 걸러진 건수 표시 / 사유 최소 2가지 카테고리 구분 / 통과+걸러짐=전체 합 일치 / 사유별 건수 DB 값 대조 가능(실측 예: 주제외77·파편63·동어반복50, 총 190건 — 화면 개발 시 DB 값 기준, 불일치①).

**의존** `claims_typed`(trivial, trivial_reason).

### 에픽 5. 규제 현황판(화면2)

#### SW-TL-01 3레인 규제 타임라인(미국/EU/한국) [미착수] — P0 · 3일

**목적** "각 관할권 규제가 어디까지 왔는가"를 한 화면에서 비교 — GENIUS Act·MiCA·한국 법안을 한눈에 보는 구조 자체가 코인 매체 기사에 없는 가치.

**입력** 3개 관할권 마일스톤 — 초기엔 자동 추출보다 **수작업 큐레이션 우선**(정확성 우선 원칙).

**처리** 레인별 마일스톤 수작업 선별(출처: `articles`, 1차 사료는 SW-PL-04 이후) → 가로축 시간 타임라인 배치 → 신규 사건 추가 절차 정의.

**예외** 마일스톤 출처가 단일 매체·낮은 신뢰도뿐이면 배치 보류(큐레이션 게이트 — 화면2는 정확성 최우선이라 자동 유입 금지).

**AC** 3레인 동시 비교 / 레인당 최소 3개 마일스톤 / 날짜·출처 각각 확인 가능 / 신규 사건 추가 절차 존재.

**의존** `articles`(source, link), SW-PL-04 산출물(확보 시).

#### SW-TL-02 AML·제재 레인 + 근거카드 [미착수] — P0 · 2일

**목적** 컴플라이언스 관점에서 가장 즉각적인 실무 트리거(제재·동결)를 별도 레인으로 노출.

**입력** AML·제재 성격 주장. 주의 — PRD의 "이미 확보된 고신뢰 18건"과 verdict='contradicted' 18건이 명칭상 겹치나 **서로 다른 집합일 가능성이 높음**: 착수 전 태그 기준(규제100건·리스크94건이 출발점)으로 AML·제재 주장을 별도 추출할 것.

**처리** AML·제재 키워드/카테고리로 주장 추출 → SW-TL-01과 별도 레인 배치 → 클릭 시 근거 카드(원문·신뢰도·관련 주장) 오픈.

**예외** 원문 링크가 죽은 경우(404) 캐시된 제목·매체명만이라도 표시(완전 실패로 화면이 깨지지 않게).

**AC** AML·제재 사건 별도 레인 표시 / 클릭 시 근거 카드+원문 링크 / 카드에 신뢰도 노출 / 레인 내 최소 3건 상호작용 가능.

**의존** `claims`, `tags`.

### 에픽 6. 질의 대응 검증기(화면3) — 핵심 차별화

#### SW-VF-01 5단계 판정 게이트 로직 [미착수] — P0 · 4일

**목적** "판정 규칙은 코드, LLM은 대조·요약만"이라는 설계 원칙을 실제 동작 코드로 증명 — 제품 전체 신뢰성 주장의 근거.

**입력** 주장 1건(claim, confidence, verdict, type, 시장 대조 결과 유무).

**처리** 결정론적 규칙으로 5단계 게이팅:
1. 수치형 + SW-PL-09 자동 대조 성공 → **수치로 확인됨**
2. 교차보도 ≥2건(동일 사건 복수 article_id) + confidence 임계값 이상 → **복수 보도 확인**
3. 교차보도 1건 + confidence 임계값 이상 → **단일 보도**
4. type='예정형' → **예정·미확정**
5. type='의견형' → **의견**

**출력** 등급(5종 중 1개) + 게이팅에 사용된 신호 값(감사용 로그).

**예외** 어느 규칙에도 안 걸리면(수치형인데 대조 실패 등) 다음 낮은 등급으로 폴백. LLM이 등급을 직접 결정하지 않는다는 경계를 코드 구조로 강제 — **등급 결정 함수에 LLM 호출 자체가 없어야 함**.

**AC** 5등급 각각 코드 규칙 존재(LLM 없이 등급 결정) / 동일 입력 반복 실행 시 동일 등급(비결정성 없음) / 최소 10건 샘플 사람 검수 일치율 보고 / LLM 관여(대조·요약)·비관여(등급 결정) 지점 코드 구조상 분리.

**의존** `claims`(confidence, verdict), `claims_typed`(type), SW-PL-09 대조 결과.

#### SW-VF-02 질의 입력 → 근거 매칭 엔진 [미착수] — P0 · 3일

**목적** "삼성이 발행 확정했다던데?" 류 자유 입력에 즉시 검증된 근거를 찾아준다 — 이게 없으면 화면3은 브리핑 재탕.

**입력** 자유 텍스트 문장 또는 기사 URL.

**처리** (a) URL 입력 → `articles.id`(=URL 자체, 실측 스키마 확인)로 존재 여부 직접 조회 → 있으면 관련 `claims` 즉시 반환. (b) 문장 입력 → 키워드 매칭으로 시작(697건 claim 텍스트 LIKE/전문검색) → 후보 반환 → SW-VF-01 게이트 통과 → 등급과 함께 응답. 필요 시 임베딩 검색 확장.

**출력** 관련 주장 후보 목록(0건 이상)+각 등급, 또는 "관련 근거 없음" 명시.

**예외** 임베딩 확장 전까지 키워드 매칭 실패 시 "관련 근거 없음"을 정직하게 반환(억지로 낮은 관련도 결과를 끼워 넣지 않음). URL이 없는 기사의 즉시 재검증 파이프라인 투입은 이번 범위 제외(미확정).

**AC** 임의 문장 입력 시 후보 ≥1건 반환 또는 "관련 근거 없음" 명시 / URL 입력 시 기존 존재 여부 판별 / 매칭 결과가 SW-VF-01 게이트 거쳐 등급과 함께 반환 / 응답 시간이 발표 데모(30초 판정) 기준에 지장 없음.

**의존** `articles.id`(URL, PK), `claims.claim`(697건 텍스트).

#### SW-VF-03 근거 출처·신뢰도 표시 UI [미착수] — P0 · 1.5일

**목적** 등급만 보여주고 근거를 숨기면 블랙박스 — 근거 노출이 신뢰의 최소 장치.

**처리** SW-VF-02 매칭 결과를 등급 배지(색상/라벨) + 근거 기사 목록(원문 링크) + 각 근거의 신뢰도 값으로 렌더.

**예외** 근거 없는 등급("의견"·"예정·미확정")에서도 화면이 깨지지 않고 "이 주장은 사실 검증 대상이 아닙니다" 류 안내로 대체.

**AC** 등급 시각 배지 구분 / 근거 원문 목록·링크 노출 / 근거별 신뢰도 표시 / 근거 없는 경우 정상 안내.

**의존** SW-VF-02 출력.

### 에픽 7. 데이터 분석 리포트(화면4)

#### SW-RP-01 매체별 판정·신뢰도 분포 분석 [부분완료 — 원재료만] — P0 · 2일

**목적** "신뢰도 0.6에 43% 집중=미보정"이 이 프로젝트 분석력의 핵심 근거. 매체별 판정 분포는 어느 코인 매체가 신뢰하기 어려운지 정량 지목.

**처리** SQL 집계(`GROUP BY source, verdict` / 신뢰도 구간별 카운트) → 차트 렌더(막대 또는 히트맵으로 0.6 집중 강조).

**예외** 표본 적은 매체(BeInCrypto 5건, Blockworks 1건 등)는 비율 대신 절대 건수 병기(비율만 보여주면 과장 위험).

**AC** 매체별 판정 분포 조회 / 0.6 집중 수치 확인(**실측 42.9%, 299/697 — 확정**) / 오보 경향 매체 최소 1곳 식별(contradicted 비율 SQL 산출 필요, 미착수) / 화면4 실제 렌더링.

**의존** `claims`, `articles.source`. 원재료(verdict 분포·0.6 집중)는 §6에 확보 — 남은 일은 매체별 교차 집계와 렌더.

#### SW-RP-02 AI 오판 3유형 정량화 [미착수] — P0 · 2일

**목적** contradicted 18건을 "시간축 혼동/사전지식 우선/출처 신뢰 오판" 3유형으로 라벨링 — AI 한계를 스스로 짚는 분석력, 발표에서 가장 설득력 있는 슬라이드 후보.

**입력** `claims WHERE verdict='contradicted'`(실측 18건) + SW-PL-03 골드셋 결과.

**처리** 18건 원문 대조 → 3유형 라벨링(복수 태깅 여부는 착수 시 결정) → 유형별 건수·대표 사례 정리.

**예외** 3유형 어디에도 안 맞으면 "기타"로 분리하고 임의로 끼워 맞추지 않는다.

**AC** 18건 전체 라벨링 / 유형별 건수 집계·최다 유형 확인 / 유형별 사례 최소 1건 근거 제시 / 화면4·SW-OP-03 양쪽 재사용 가능한 형태 정리.

**의존** `claims`(contradicted 18건, 실측 확인 완료).

#### SW-RP-03 한/영 매체 프레이밍 비교 + 주장 유형 비율 [미착수] — P1 · 2.5일

**목적** 국내외 매체가 같은 사건을 다르게 포장하는 패턴을 정량으로 — "왜 검증이 필요한가" 설득력 보강. 핵심 판정 기능 완성 뒤 붙여도 되는 확장 분석.

**입력** `articles.lang`(en 222 / ko 88) × `claims_typed.type` 교차.

**처리** 언어별 표현 차이(예: "검토"vs"확정" 빈도) 비교 → 유형 비율 차트. 원재료 실측 완료: 한국어 수치형 28.5% vs 영어 10.7%, 영어 사건형 56.0%·예정형 11.9%(`정제결과_요약.md` 3절).

**예외** "고신뢰" 임계값은 confidence≥0.9로 통일 표기(불일치③ — 0.8 혼용 금지).

**AC** 한/영 매체 판정·표현 경향 비교 / 최소 1개 사건 프레이밍 차이 사례 / 유형 비율 차트 조회 / SW-RP-01과 구분된 섹션으로 노출.

**의존** `articles.lang`, `claims_typed.type`.

### 에픽 8. 운영·발표

#### SW-OP-01 Vercel 자동 배포 파이프라인 [미착수] — P0 · 2일

**목적** 매일 갱신 데이터가 배포 화면에 반영되지 않으면 "데일리 브리핑"이 무색해진다. 발표 직전 수동 배포 의존은 시연 리스크.

**처리** python 파이프라인 산출물(갱신된 archive.db 또는 API 응답)을 Next.js 앱이 매일 자동 반영. 정적 빌드 재생성(예약 재배포) vs 런타임 조회(API가 DB 직접 읽음) 중 방식 결정 → Vercel 연동.

**예외** 배포 실패 시 이전 정상 버전 유지(서비스 중단 없음).

**AC** 매일 1회 이상 무개입 배포/갱신 / 배포 화면 데이터=최신 DB 일치 / 배포 실패가 중단으로 이어지지 않음 / 배포 이력 확인 가능(Vercel 대시보드).

**의존** 원본 `archive.db`(SW-PL-05 갱신분).

#### SW-OP-02 발표용 데모 시나리오 [미착수] — P0 · 2일

**목적** "삼성 발행 확정?" 류 임원 질문에 30초 안에 근거 기반으로 답하는 장면 — 제품 가치를 가장 압축적으로 보여주는 순간. 프로젝트 발표(13~15주차) 성패가 여기 좌우.

**처리** 화면3 이용 질의→판정→근거 제시 시연 스크립트 작성 → 실제 화면 최소 2회 리허설 → 실패 대비 백업(녹화본) 준비.

**예외** 라이브 데모 실패(네트워크/API 쿼터/매칭 실패) 시 즉시 녹화본 전환.

**AC** 질의→근거 제시 30초 내외 측정 / 최소 2회 실화면 리허설 / 라이브 실패 대체 수단 준비 / 시나리오 대본 문서화·공유 가능.

**의존** 화면3 전체(SW-VF-01/02/03), 데모용 질의 샘플.

#### SW-OP-03 기획서 발표 자료 [미착수] — P0 · 2일

**목적** 4~6주차 기획서 발표는 학기 방향을 검증받는 첫 체크포인트 — 문제 정의(노이즈·과장)와 기반 자산(파이프라인·697건)의 설득력이 이후 지도를 좌우.

**처리** 슬라이드 구성 → 이미 증명한 것(§6 실측 수치)과 개발할 것(화면 4종) 구분 제시 → 리허설.

**예외** 발표 시간 제한 미확인(§15) — 확인 전까지 15분 기준 초안 작성 후 조정.

**AC** 문제 정의(노이즈 30~40%, 과장 사례) 근거와 함께 포함 / 확보 자산(파이프라인·archive.db 통계) 동작 증거로 제시 / 4개 화면 컨셉·우선순위 로드맵 제시 / 발표 시간 내 리허설 완료.

**의존** §6 실측 스냅숏 전체, `data/정제결과_요약.md`.

## 11. 시장 (TAM·SAM·SOM 뼈대)
