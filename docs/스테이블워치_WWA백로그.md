# 스테이블워치(StableWatch) 제품 백로그 — WWA 형식

- 형식: Title / Why / What / Acceptance Criteria + 우선순위(P0 필수·P1 목표·P2 여유) + 예상 소요(하루 3~10시간 가정)
- 아이템 22개, 8개 에픽. 각 아이템은 독립적으로 개발 가능(순서 무관)하나, 같은 archive.db·파이프라인을 공유 자산으로 참조함.
- 일정 앵커: 개강 9/1, 기획서 발표 4~6주차, Claude Max 구독 종료 10/13(코드 무거운 작업은 그 전), 프로젝트 발표 13~15주차.

## 에픽 1. 데이터 정제 — 신뢰도 기반 다지기

### 1. 주장 유형 분류 체계 구축
**우선순위:** P0(필수) · **예상:** 2일

**Why:** 규제현황판·검증기·리포트 세 화면 모두 "이 주장이 수치인지 사건인지 예정인지 의견인지"를 전제로 판정 로직과 시각화가 달라진다. 지금 archive.db는 697건 주장에 이 축이 없어 화면 개발이 막혀 있다.

**What:** 기존 주장 697건을 수치형/사건형/예정형/의견형 4종으로 태깅하는 방법(규칙 기반 vs LLM 재분류)과 태깅 결과를 저장할 스키마 변경 범위를 정한다. 완전 자동 분류가 애매한 경계 사례(예: "OO은행이 상반기 내 출시 예정"이 사건형인지 예정형인지)를 어떻게 처리할지도 이 자리에서 논의한다.

**Acceptance Criteria:**
- 697건 주장 전체가 4개 유형 중 하나로 태깅되어 SQL로 유형별 카운트 조회 가능
- 분류 근거(규칙 vs 모델 판단)가 최소 샘플 20건에 대해 사람이 확인 가능한 형태로 기록됨
- 유형 분류 결과가 데이터 분석 리포트(화면4)와 질의 검증기(화면3) 양쪽에서 동일 필드로 참조됨
- 애매 사례 처리 기준(우선순위 규칙 등)이 문서화됨

### 2. 트리비얼 주장 필터링
**우선순위:** P0(필수) · **예상:** 1일

**Why:** "오늘 걸러진 N건과 이유" 패널(데일리 브리핑)과 신뢰도 있는 카드 피드를 위해서는 화제성 없는 반복·광고성 주장을 먼저 걸러내야 한다. 실측 30~40% 주제외 노이즈 중 상당수가 이 범주로 추정된다.

**What:** "트리비얼"의 기준(동일 사실 반복 보도, 시세 홍보성 문구, 본문과 무관한 인용 등)을 정의하고 어떤 신호(중복도, 출처 신뢰도, 주장 카테고리)로 걸러낼지 논의한다. 완전 제거가 아니라 "걸러짐" 태그로 남겨 감사 추적이 가능하게 할지도 정한다.

**Acceptance Criteria:**
- 트리비얼 판정 기준이 최소 3가지 이상 규칙으로 명문화됨
- 필터 적용 전/후 주장 건수 변화가 수치로 확인됨
- 걸러진 주장이 삭제가 아니라 "제외" 상태로 보존되어 추적 가능
- 오분류(트리비얼 아닌데 걸러짐) 샘플 검수 결과가 최소 1회 보고됨

### 3. 수동 골드셋 재검증 (30~50건)
**우선순위:** P0(필수) · **예상:** 3일

**Why:** AI 파이프라인의 판정 정확도를 주장하려면 사람이 직접 원문 대조한 표본이 있어야 신뢰도 분포(0.6 집중=미보정) 같은 발견에 근거를 댈 수 있다. 화면4 리포트와 발표 자료 모두의 근거가 된다.

**What:** 697건 중 신뢰도·판정 유형별로 층화 추출한 30~50건을 원문 기사와 대조해 사람이 직접 재판정한다. 파이프라인 판정과 사람 판정이 갈리는 경우를 기록해 두면 이후 AI 오판 3유형 분석(화면4)의 원재료가 된다.

**Acceptance Criteria:**
- 30~50건에 대해 사람 재판정 결과가 원 파이프라인 판정과 나란히 표로 기록됨
- 표본이 신뢰도 구간·판정 유형별로 층화되어 있음이 확인됨
- 사람-AI 불일치 건수와 그 사유가 정리됨
- 이 결과가 화면4 "AI 오판 3유형" 항목의 입력 데이터로 연결됨

## 에픽 2. 파이프라인 보강

### 4. 1차 사료 RSS 소스 추가
**우선순위:** P1(목표) · **예상:** 4일 — ⚠ 리스크 항목

**Why:** 코인 매체 편향(과장·노이즈)의 근본 해법은 금융위·한은·OCC·SEC·ECB 같은 1차 발표 소스를 직접 수집해 대조축으로 쓰는 것이다. "검토중→확정 둔갑" 과장을 잡아내는 핵심 근거가 된다.

**What:** 각 기관의 보도자료 페이지가 깨끗한 RSS를 제공하는지, 스크레이핑이 필요한지부터 조사가 필요하다. 5개 기관을 같은 방식으로 통합하기보다 기관별 파서를 두는 구조가 될 가능성이 높다는 점을 논의 대상으로 남긴다.

**Acceptance Criteria:**
- 5개 기관 중 최소 3곳 이상에서 신규 항목이 자동으로 collector에 유입됨
- 신규 소스 문서가 기존 archive.db 스키마(URL 보유 포함)에 정합적으로 저장됨
- 소스별 수집 성공/실패 로그가 남아 장애 시 원인 추적 가능
- 신규 소스로 확인된 사건이 화면2(규제 현황판)에서 최소 1건 표시됨

---

### 5. 일일 수집 자동 재개
**우선순위:** P0(필수) · **예상:** 1.5일

**Why:** 데일리 브리핑과 규제 현황판이 살아있는 도구로 보이려면 수집이 중단 없이 매일 돌아야 한다. 5월부터 운영해온 파이프라인이 있으나 최근 공백이 발생한 상태다.

**What:** 기존 collector→analyst→critic→synthesizer 체인을 스케줄러(cron 또는 GitHub Actions 등)에 올려 매일 자동 실행되게 하는 작업이다. API 쿼터(Gemini/Groq)를 고려한 실행 시간대·재시도 정책은 실행하며 조정한다.

**Acceptance Criteria:**
- 최소 3일 연속 자동 수집이 사람 개입 없이 완료됨
- 실행 실패 시 알림 또는 로그로 확인 가능
- API 쿼터 초과로 인한 실패가 재시도 또는 알림으로 처리됨
- 신규 수집분이 archive.db에 기존 스키마 그대로 누적됨

---

### 6. 8월 데이터 공백 백필
**우선순위:** P0(필수) · **예상:** 2일

**Why:** 8월 공백은 데일리 브리핑의 최신성과 화면4 분석의 시계열 연속성을 깬다. 학기 시작 전에 메꿔야 개강 직후 화면들이 "최근 데이터 없음"으로 보이지 않는다.

**What:** 8월 기간 기사를 소급 수집할 수 있는 방법(날짜 지정 검색 API, 과거 URL 목록 확보 등)을 확인하고 기존 파이프라인에 그대로 태워 처리한다. 완전한 소급이 어려운 기간은 공백으로 명시하고 넘어가는 것도 논의 대상이다.

**Acceptance Criteria:**
- 8월 기간 신규 기사가 archive.db에 추가되어 건수가 확인됨
- 백필된 주장도 기존 697건과 동일한 검증 단계(supported/uncertain/contradicted)를 거침
- 완전히 메꿀 수 없는 잔여 공백이 있다면 그 기간이 명시적으로 문서화됨
- 화면1·화면4에서 8월 데이터가 정상적으로 조회됨

## 에픽 3. 시장 데이터 연동

### 7. 글로벌 시장 데이터 연동 (DefiLlama + CoinGecko)
**우선순위:** P1(목표) · **예상:** 1.5일

**Why:** 수치형 주장("발행량 OO억 달러 돌파" 등)을 실제 시장 숫자와 대조하려면 외부 시세·발행량 데이터가 있어야 한다. 이 둘은 공개 REST API로 인증 없이 접근 가능해 상대적으로 빠르게 붙일 수 있는 축이다.

**What:** 어떤 스테이블코인 종목을 추적 대상으로 할지(USDT, USDC, 원화 스테이블코인 후보 등), 수집 주기(실시간 vs 일 배치), 화면3·화면4 어디서 이 데이터를 쓸지 범위를 정한다.

**Acceptance Criteria:**
- DefiLlama 발행량 데이터가 최소 3개 종목에 대해 조회됨
- CoinGecko 가격·시총 데이터가 동일 종목에 대해 조회됨
- 데이터가 일정 주기로 갱신되어 최신 시점 값이 유지됨
- 이 데이터를 참조하는 화면(3 또는 4)에서 최소 1곳에 노출됨

---

### 8. 국내 거래소 원화 마켓 연동 (업비트·빗썸)
**우선순위:** P2(여유) · **예상:** 1.5일

**Why:** 한국 은행 컴플라이언스 청중에게는 원화 마켓 시세가 달러 표시 시세보다 체감 근거로 더 잘 통한다. 다만 이는 글로벌 데이터 연동(항목7)이 검증된 뒤에 추가해도 되는 확장이다.

**What:** 업비트·빗썸 공개 API로 원화 마켓 가격을 가져와 항목7의 글로벌 데이터와 나란히 보여줄지, 특정 화면에만 보조적으로 쓸지를 정한다.

**Acceptance Criteria:**
- 업비트·빗썸 중 최소 1곳의 원화 시세가 조회됨
- 조회 데이터가 항목7의 글로벌 시세와 같은 형식으로 정규화됨
- 원화 마켓 데이터가 없는 종목에 대한 처리(공란 표시 등)가 정해짐
- 최소 1개 화면에서 원화 시세가 실제로 노출됨

---

### 9. 수치 주장-시장데이터 자동 대조 (+ 병치 폴백)
**우선순위:** P1(목표) · **예상:** 3일 — ⚠ 리스크 항목

**Why:** 질의 대응 검증기(화면3)의 "수치로 확인됨" 등급이 실제로 힘을 가지려면 주장 속 숫자와 시장 데이터를 기계적으로 대조하는 로직이 있어야 한다. 다만 자연어 주장에서 종목·시점·수치를 정확히 추출하는 일은 난이도가 높아 자동 매칭이 막힐 가능성을 미리 열어둔다.

**What:** 자동 대조가 가능한 범위(종목명이 명시된 발행량 주장 등)부터 시도하고, 매칭이 애매한 경우 자동 판정 대신 "수치 주장 옆에 관련 시장 차트를 나란히 배치"하는 축소안으로 전환하는 기준을 논의한다.

**Acceptance Criteria:**
- 최소 10건의 수치형 주장에 대해 자동 대조 또는 병치 표시 중 하나가 적용됨
- 자동 대조 성공률(전체 수치형 주장 대비)이 수치로 보고됨
- 매칭 실패 시 병치 폴백으로 전환되는 경로가 실제로 동작함
- 대조 결과가 화면3의 판정 등급에 실제로 반영됨

## 에픽 4. 데일리 브리핑 (화면1)

### 10. 검증 통과 주장 카드 피드
**우선순위:** P0(필수) · **예상:** 2일

**Why:** 컴플라이언스 담당자가 매일 아침 훑어볼 첫 화면으로, "검증을 통과한 주장만 보여준다"는 제품의 핵심 약속을 가장 먼저 체감시키는 자리다.

**What:** 주장·신뢰도·판정·원문 링크가 카드 단위로 나열되는 화면이다. 정렬 기준(최신순 vs 신뢰도순), 카드당 정보량, 원문 링크 클릭 시 새 탭 여부 등은 화면을 붙이며 정한다.

**Acceptance Criteria:**
- 최근 검증 통과 주장이 카드 형태로 목록 조회됨
- 각 카드에 주장 텍스트·신뢰도·판정·원문 URL이 모두 노출됨
- 원문 링크 클릭 시 실제 기사로 이동함
- 데이터 없는 날짜에 대해 빈 상태 화면이 별도로 처리됨

---

### 11. 오늘 걸러진 건수와 사유 패널
**우선순위:** P0(필수) · **예상:** 2일

**Why:** "걸러진 것도 투명하게 보여준다"는 태도가 이 도구를 다른 자동 요약 도구와 구분 짓는 지점이며, 항목2(트리비얼 필터)의 산출물을 실제 사용자에게 노출하는 자리다.

**What:** 오늘 걸러진 주장 건수와 대표 사유(트리비얼/신뢰도 미달/모순 등)를 요약해 보여주는 패널이다. 걸러진 개별 항목까지 펼쳐 보여줄지, 건수+사유 요약만 보여줄지는 논의 대상이다.

**Acceptance Criteria:**
- 당일 걸러진 주장 건수가 화면에 표시됨
- 걸러진 사유가 최소 2가지 이상 카테고리로 구분되어 표시됨
- 카드 피드(항목10)의 통과 건수와 걸러진 건수 합이 그날 전체 처리 건수와 일치함
- 사유별 건수가 실제 archive.db 값과 대조 가능함

## 에픽 5. 규제 현황판 (화면2)

### 12. 3레인 규제 타임라인 (미국/EU/한국)
**우선순위:** P0(필수) · **예상:** 3일

**Why:** 은행 TF·컴플라이언스 담당자가 가장 자주 찾는 정보가 "각 관할권 규제가 지금 어디까지 왔는가"이며, GENIUS Act·MiCA·한국 법안 진행 상황을 한 화면에서 비교하는 구조 자체가 코인 매체 기사에는 없는 가치다.

**Acceptance Criteria:**

- LLM이 관여하는 지점(대조·요약)과 관여하지 않는 지점(등급 결정)이 코드 구조상 분리되어 있음
