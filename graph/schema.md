# 근거 그래프 스키마

작성 2026-09-10, 개정 같은 날(적대검증 2차 반영). 스키마 우선(OG-RAG 방식)으로 빈칸을 먼저 고정하고, 조문 단위 출처(법률 지식그래프 방식)를 간선마다 붙인다. AI는 간선 후보만 제안하고, 확정은 사람이 한다. 검사는 `scripts/validate_graph.py`가 한다.

## 노드

| 종류 | ID 형식 | 예 |
|---|---|---|
| 규칙 축 | `R01`~`R15`(해외 비교 축), `K01`~`K05`(한국 열을 따로 봐야 하는 축), `K06`~(후보) | `R05` 은행 예치 최소 비율, `K01` 컨소시엄 구조 |
| 문서 | `graph/corpus.json`의 `id` | `law:전자금융거래법:254921`, `bill:2211784`, `gov:fsc:86373`, `foreign:us:GENIUS` |
| 조문 | 문서 ID + 조문 | `law:전자금융거래법:254921#제25조의2제1항` |

## 근거층 (문서마다 하나)

| 층 | 뜻 | 읽는 법 |
|---|---|---|
| 1 | 시행 법률, 시행령, 감독규정 | 이 층에 간선이 있으면 현행 의무 또는 유사 선례 |
| 2 | 국회 계류 법안 | 이 층에만 있으면 입법 대기, 값은 후보 |
| 3 | 정부, 한국은행, 국회 공식 자료 | 발행 기관과 문장의 역할을 `role`에 적는다. 정부 검토 방향, 한은 의견, 국회 검토보고서의 법안 비교나 검토자 의견은 서로 다른 무게다 |
| 4 | 언론 보도 | 원문을 못 찾은 정책 방향은 여기 |
| 5 | 업계 관행 | 이 층에만 있으면 제도화 후보 |
| foreign | 해외 규정 | 비교용. 한국 층이 아니다 |

## 간선 (`graph/edges/<축>.json` 한 줄이 간선 하나)

| 필드 | 뜻 |
|---|---|
| `axis` | 규칙 축 ID |
| `layer` | 1~5 또는 `foreign`. 갭 기록은 null |
| `doc` | 문서 ID |
| `article` | 조문 번호 또는 페이지. 조문을 못 정했으면 "원문 N행(조문 번호 미확인)" |
| `date` | 법률은 시행일, 법안은 발의일, 자료는 게시일 |
| `quote` | 원문 그대로. 생략은 `(...)`로만 표시하고, 괄호 보충은 넣지 않는다. 화면용 축약문은 `summary`에 따로 둔다 |
| `value` | 숫자면 숫자. 기간이나 주기처럼 단위가 있으면 문자열에 단위를 포함한다. 없으면 null. `unit`으로 종류(비율, 일수, 영업일, 금액, 주기)를 적을 수 있다 |
| `url` | 원문 링크 |
| `verified` | `true` 원문에서 인용 전체를 대조함. `"partial"` 일부 세그먼트만 일치하거나 요약 인용. `false` 미대조 |
| `verified_by` | 대조 수단. `law.go.kr DRF XML`, `PDF pdftotext`, `WebFetch`, `curl HTML` |
| `confirmed` | 사람이 확정했으면 true. 기본 false |
| `confirmed_by`, `confirmed_at` | 확정한 사람과 날짜. confirmed가 true면 필수 |
| `role` | 3층에서 문장의 역할. `정부 검토 방향`, `한은 의견`, `국회 법안 비교`, `검토자 의견` |
| `note` | 층 오분류, 한계, 퍼플렉시티 오류 정정, 검사 결과 |

## 확정(confirmed) 조건

사람이 다음 넷을 직접 확인한 뒤에만 true로 바꾼다. 확인한 사람과 날짜를 적는다.
1. 링크를 열어 인용이 원문에 있다.
2. 적용 대상이 맞다(발행사인지 거래소인지 선불업자인지, 일반인지 중요 토큰인지).
3. 예외와 위임이 있으면 note에 적었다.
4. 값의 단위와 기준(액면인지 시가인지, 영업일인지 달력일인지)이 적혀 있다.

확정되지 않은 간선은 규칙 엔진의 관할권 설정(`jurisdictions/*.json`)에 들어가지 않는다. 설정 파일은 어느 간선을 근거로 값을 정했는지 간선 ID를 적는다.

## 상태 체계 (판정과 갭 목록이 쓰는 값)

| 상태 | 뜻 | 어디로 가나 |
|---|---|---|
| 충족, 미충족, 주의 | 요건도 데이터도 있어서 판정함 | 판정표 |
| 데이터 없음 | 요건은 있는데 보고서에 필드가 없음 | 파서 백로그 |
| 위임 예정 | 요건은 있는데 값이 시행령이나 고시에 위임됨 | 갭 목록(위임으로 표시) |
| 규정 없음 | 그 관할권 어느 층에도 요건이 없음 | 갭 목록 |
| 조사 미완료 | 코퍼스 명세의 문서를 아직 다 보지 않음 | 조사 목록. 갭으로 세지 않는다 |

## 갭 확정 절차

"못 찾은 것"과 "없는 것"을 가르는 기준이다. 아래 넷이 다 채워져야 규정 없음으로 확정한다.
1. 조사 범위: `corpus.json`의 1층 문서 전부와 2층 법안 전부를 검색어와 함께 기록한다.
2. 위임 확인: 법률에 값이 없어도 시행령이나 고시에 위임됐으면 위임 예정으로 둔다.
3. 유사 제도 준용 확인: 전금법 선불충전금, 이용자보호법 예치금처럼 구조가 같은 제도가 직접 적용되는지 본다. 적용되면 규정 없음이 아니다.
4. 반증 가능성: 어떤 문서가 나오면 갭이 아니게 되는지 한 줄로 적는다.

## 규칙

- 인용은 문서 텍스트에 부분 문자열로 존재해야 한다(공백 제거 후). `(...)`로 나눈 세그먼트마다 검사한다. 불일치면 `verified`를 `"partial"`로 내리고 폐기하지는 않는다.
- 4층 내용을 1층이나 3층에 올리지 않는다. 기사가 정부 방침을 인용해도 원문을 못 찾으면 4층이다.
- 법안은 의안번호로만 구분한다.
- 같은 내용이 여러 층에 있으면 층마다 간선을 따로 둔다.
- 값 선택(한국안 v1)은 간선이 아니라 별도 결정 기록(`graph/decisions/`)에 쓴다. 채택값, 기각한 대안, 이유, 바뀌는 조건을 적는다.
