# 근거 그래프 스키마

작성 2026-09-10. 스키마 우선(OG-RAG 방식)으로 빈칸을 먼저 고정하고, 조문 단위 출처(법률 지식그래프 방식)를 간선마다 붙인다. AI는 간선 후보만 제안하고, 확정은 사람이 한다.

## 노드

| 종류 | ID 형식 | 예 |
|---|---|---|
| 규칙 축 | `R01`~`R15`(해외 15), `K01`~`K05`(한국 5) | `R05` 은행 예치 최소 비율, `K01` 컨소시엄 구조 |
| 문서 | `corpus.json`의 `id` | `law:전자금융거래법:254921`, `bill:2211784`, `gov:fsc:86373` |
| 조문 | 문서 ID + 조문 | `law:전자금융거래법:254921#제25조의2제1항` |

## 근거층 (문서마다 하나)

| 층 | 뜻 | 갭 판정 |
|---|---|---|
| 1 | 시행 법률, 시행령, 감독규정 | 이 층에 간선이 없으면 갭 |
| 2 | 국회 계류 법안 | 이 층에만 있으면 입법 대기 |
| 3 | 정부와 한국은행 공식 자료 | 검토 방향 |
| 4 | 언론 보도 | 보도 단계 |
| 5 | 업계 관행 | 이 층에만 있으면 제도화 후보 |

## 간선 (`graph/edges/<축>.json` 한 줄이 간선 하나)

| 필드 | 뜻 |
|---|---|
| `axis` | 규칙 축 ID |
| `layer` | 1~5 |
| `doc` | 문서 ID |
| `article` | 조문 번호 또는 페이지 |
| `date` | 법률은 시행일, 법안은 발의일, 자료는 게시일 |
| `quote` | 원문 그대로, 200자 이내 |
| `value` | 숫자로 떨어지면 숫자, 아니면 null |
| `url` | 원문 링크 |
| `verified` | 원문에서 인용을 대조했으면 true |
| `verified_by` | 대조 수단. `law.go.kr DRF XML`, `PDF pdftotext`, `page fetch` |
| `confirmed` | 사람이 확정했으면 true. 기본 false |
| `note` | 층 오분류, 한계, 퍼플렉시티 오류 정정 등 |

## 규칙

- 인용은 문서 텍스트에 부분 문자열로 존재해야 한다. 없으면 `verified: false`로 남기고 폐기하지 않는다.
- 4층 내용을 1층이나 3층에 올리지 않는다. 기사가 정부 방침을 인용해도 원문을 못 찾으면 4층이다.
- 법안은 의안번호로만 구분한다.
- 같은 내용이 여러 층에 있으면 층마다 간선을 따로 둔다.
- 값 선택(한국안 v1)은 간선이 아니라 별도 결정 기록에 쓴다.
